โครงสร้างฟิลด์ทั้งหมดของ Block

4 แท็บ: Block/Slab × Required/Optional

  • Block (Required) — ต้องกรอกตอนรับก้อนเข้าคลัง: รหัสก้อน, Material, Quality, Supplier, Warehouse
  • Block (Optional) — รายละเอียดเสริมของก้อนดิบ: Block Number (เลขจริงจากเหมือง), Container ที่มาด้วย, Rack Location, วันที่คาด/รับจริง
  • Slab (Required) — Finish + ราคาขาย/ตร.ม. ของแผ่นที่จะตัดจากก้อนนี้
  • Slab (Optional) — ต้นทุน/ตร.ม. ทุกชั้น (PO/Landed/รวม), ลิงก์ไปยัง Stock Lot ของ Odoo มาตรฐาน, สถิติพื้นที่รวม
ทำไมแยก Required/Optional: กันพนักงานหน้างานสับสน — ตอนรับของจริงกรอกแค่ Required ก็เพียงพอ ส่วน Optional เป็นข้อมูลที่ทยอยเติมได้ทีหลังหรือใช้เฉพาะบางเคส
จุดที่ทีมงานเคยสับสน

Block Code กับ Block Number คนละอันกัน

?
ทำไมมี 2 ฟิลด์ที่ดูคล้ายกัน
"Block Code" (เช่น BLK-26-0004) คือรหัสที่ระบบออกให้อัตโนมัติ ส่วน "Block Number" คือเลขก้อนจริงจากเหมืองหิน (เช่น E2111-260) — คนละที่มา คนละเลข
  • Block Code ออกอัตโนมัติจากเลขรัน (BLK-%(y)s- + เลข 4 หลัก รีเซ็ตทุกปี) — พนักงานพิมพ์เองแทนได้ถ้าต้องการคงเลขเดิมจากโปรเจกต์เก่า ระบบจะออกเลขให้เฉพาะตอนเว้นว่างไว้
  • Block Number เป็นช่องอิสระ ไว้บันทึกเลขก้อนจริงที่เหมืองสลักมาให้ — ไม่ผูกกับการออกเลขอัตโนมัติใดๆ
  • ก่อนหน้านี้ระบบเคยติดป้ายชนกัน (ทั้งคู่ใช้คำว่า "Block Number") จนเจอ warning ตอนอัปเกรด 2026-08-16 — แก้แล้วโดยเปลี่ยนรหัสอัตโนมัติเป็น "Block Code"
รูปแบบเลขเก่า: ก้อนที่รับเข้าก่อน 2026-08-16 ยังคงใช้รหัส BDL-xxxxx เดิม — ระบบไม่ไปแก้เลขที่ออกไปแล้ว เปลี่ยนแค่รูปแบบเลขใหม่ที่จะออกต่อจากนี้

สูตรคำนวณจาก
Cost / Sq.Mt.Cost / CBM × Thickness (m) — ค่าเดียวทั้ง Block
PO Cost / Sq.Mt.ราคาซื้อจาก PO / CBM × Thickness
Landed Cost / Sq.Mt.รวมค่าขนส่ง+ภาษีนำเข้าที่กระจายสัดส่วนแล้ว / CBM × Thickness
ส่วนที่เป็น Odoo มาตรฐาน: ทุก Block ผูกกับ stock.lot จริงของ Odoo อัตโนมัติ (เช่น BLK-26-0004-LOT) — ใช้ระบบติดตาม Lot/Serial มาตรฐานเป็นฐาน ส่วนสูตรต้นทุนต่อตร.ม.และการรวมยอด Available/Hold/Sold Sqmt คือโค้ด custom ที่สร้างเพิ่มบนฐานนั้น
ข้อจำกัดที่ทีมงานต้องรู้

1 Block เก็บได้แค่ 1 ความหนา

!
สาเหตุทางเทคนิค
thickness_m เป็นฟิลด์เดียวอยู่บนตัว Block เอง (ไม่ใช่ต่อแผ่น) — ทุกแผ่นที่ตัดจาก Block เดียวกันจึงต้องหนาเท่ากันหมด เพราะสูตรต้นทุนทั้งหมดอ้างอิงความหนานี้ค่าเดียว
  • ถ้าต้องการตัดก้อนเดียวกันหลายความหนา (เช่น 2cm สำหรับ Countertop, 3cm สำหรับพื้น) — ต้องแยกสร้างเป็น 2 Block รายการจากก้อนหินตั้งต้นเดียวกัน แบ่งโควตา CBM ให้แต่ละรายการ
  • เป็นการตัดสินใจทางออกแบบ ไม่ใช่ข้อจำกัดที่แก้ไม่ได้ — เลือกทำแบบนี้เพื่อให้สูตรต้นทุนต่อตร.ม.เรียบง่ายและตรวจสอบย้อนกลับได้ชัดเจนต่อ 1 รายการ
  • ทีมงานต้องตัดสินใจแบ่งความหนาตั้งแต่ขั้นรับก้อนเข้าคลัง ไม่ใช่ทีหลัง
ถ้าลูกค้ามีเคสนี้บ่อย: ทีมจะเตรียมคำแนะนำการตั้งค่าและอาจพิจารณาทำ wizard ช่วยแบ่ง Block อัตโนมัติในอนาคต
