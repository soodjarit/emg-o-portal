จุดที่เหมือนกันทุก Mode

ไม่ว่าจะ Mode ไหน 3 กลไกนี้ใช้ร่วมกันหมด

  • 1ทุก Mode ผ่าน security group เดียวกัน (group_emgo_internal_user / manager) — ไม่ใช้ company_id + ir.rule แบบโมดูลอื่นในระบบ
  • 2ทุก Mode ที่มีการ deliver จริง ผ่าน scan-verification guard เดียวกันตอน validate delivery (ADR-009) — สแกน lot ยืนยันก่อนส่งของเสมอ
  • 3ทุก Mode ที่มีต้นทุนวัตถุดิบ ผูกกับ Analytic Account ชุดเดียวกัน (Cost-by-Material Architecture, ADR-056) — ไม่แยกระบบบัญชีตาม Mode

Mode 4 ไม่ใช่ "ประเภทสินค้า" แบบ 1/2/3/5 — เป็นชั้นครอบ (overlay)

!
ทำไมถึงต้องแยกไว้
Mode 1/2/3/5 คือกลไกจัดการ "สินค้าจริง" (Block/Slab/FG) แต่ Mode 4 เป็นแค่ตัวเลือก opt-in ที่ครอบ SO ทั้งใบ (สร้าง Project + Gantt) — line สินค้าข้างในของ SO ที่เป็น Mode 4 ยังต้องเป็น Mode 1/2/3/5 อย่างใดอย่างหนึ่งอยู่ดี
สรุป: ถ้าจะเทียบ "5 Mode" แบบแยกขาดจากกัน (mutually exclusive) จะไม่ตรงเป๊ะ — Mode 4 ซ้อนทับกับอีก 4 Mode ได้พร้อมกัน ไม่ได้อยู่ในแกนเดียวกับ Block/Slab/FG

สรุป

3 ประเภทสินค้า + Custom Hold ที่จำเป็น = เหตุผลที่ยังต้องมี 5 Mode

คำถามคำตอบ
ยุบเหลือ 3 ประเภทสินค้า (Block/Slab/FG) แทน 5 Mode ได้ไหมยุบเป็นกรอบคิดได้ (helpful mental model) แต่ยุบเป็นกลไกจริงไม่ได้ — Block/Slab ยังต้อง custom hold เสมอ
ของอยู่ใน stock แล้ว ขาย native ได้เลยไหมBlock/Slab: ไม่ได้ ยังต้องผ่าน Select wizard — FG: ได้ใกล้เคียง native (ไม่มี custom hold)
Mode 3 กับ Mode 5 เหมือนกันไหมPattern เดียวกัน (native MO ไม่มี wizard) แต่ input/output ต่างกัน — 3 ใช้ Block→N Slab (serial), 5 ใช้ Slab→FG (lot รวม)
Mode 4 นับเป็น Mode ที่ 6 ของสินค้าไหมไม่ — เป็น overlay ที่ครอบ SO ทั้งใบ ไม่ใช่ประเภทสินค้า
เก็บไว้เป็นบันทึกอ้างอิง — ถ้าอนาคตมีคำถามเรื่องโครงสร้าง 5 Mode อีก กลับมาดูหน้านี้ก่อนออกแบบใหม่
