กรอกรายละเอียดก้อน → Save = รับเข้าสต็อกอัตโนมัติ

  • กรอก Quality, Warehouse (Company ดึงจาก Warehouse อัตโนมัติ)
  • กด Save — ระบบสร้าง+validate stock receipt ให้เองทันที (_ensure_block_stock_received) ยืนยันด้วย SQL จริง: 5.00 m³ เข้า Stone Available ทันทีที่ Save
BLK-26-0005 บันทึกสำเร็จ — Block Code ออกอัตโนมัติ ครบทุกฟิลด์
ข้อควรระวังจริง (ยืนยันจากทั้งโค้ดและระบบจริง): ห้าม validate ใบรับสินค้า (Purchase Receipt) ปกติซ้ำ — พอมี Block ผูกกับ PO Line แล้ว ระบบยกเลิกใบรับให้เองทันที (_ensure_receipt_cancelled, เห็นสถานะ "Cancelled" จริงใน EG01/IN/00003) กันข้อมูลสต็อกชนกัน
อัปเดตเพิ่มเติม แท็บ "Block (Optional)" มีฟิลด์เสริมที่ไม่ได้เดินในเดคนี้: Container (ผูกก้อนที่มากับตู้เดียวกัน ใช้ allocate ค่า Freight/Duty ข้าม Block โดยอัตโนมัติ — optional ไม่บังคับ) และ Length/Width/Height (ขนาดวัดจริงตอนรับเข้า เก็บไว้อ้างอิงเท่านั้น ไม่กระทบ CBM/ราคา)

  • แต่ละแผ่นเก็บสถานะของตัวเอง (Available ทันทีที่บันทึก)
Slab #1 — 2.80 × 1.60 ม. = 4.48 ตร.ม. สถานะ Available ทันที (Total 1 / Available 1)
ข้อควรระวังจริง: ถ้าจะขายแบบแยกแผ่นในอนาคต ต้องกรอกทั้ง "Slab L/H" (ขนาดจริงที่ตัดได้) และ "Purchased L/H" (ขนาดที่ใช้คิดราคา) — ราคาขายคำนวณจาก Purchased Sqmt เท่านั้น ถ้ากรอกแค่ Slab L/H เฉยๆ ราคาจะเป็น 0 บาททันที (Purchased L มักเติมให้อัตโนมัติ แต่ Purchased H ต้องกรอกเองเสมอ)

รับหินเข้าคลัง — 6 ขั้นตอน จาก PO ถึงพร้อมขาย

สิ่งที่ทำเอง
เปิด PO → Confirm → สร้าง Block ผูก PO Line → กรอก Material/Quality/Warehouse → Save → เพิ่มแผ่น Slab
สิ่งที่ระบบทำให้อัตโนมัติ
ดึง Supplier+CBM จาก PO Line → สร้าง+validate stock receipt → บล็อกใบรับสินค้าปกติไม่ให้ validate ซ้ำ
ข้อควรระวังจริง
ห้าม validate Purchase Receipt แบบปกติ — ต้องสร้าง Block ผูกกับ PO Line เท่านั้นถึงจะรับเข้าคลังถูกต้อง
อัปเดตเพิ่มเติม ตั้งแต่ 20 ส.ค. 2026 แต่ละ Slab มี Labor Cost + Total Cost แยกให้อัตโนมัติ (ต้นทุนวัสดุ + ค่าแรงตัด) — ถ้าตัดผ่าน Cut-to-Order ใช้ต้นทุนจริงจาก Work Order, ถ้าเพิ่มแผ่นแบบ manual (ตามเดคนี้) ใช้ flat rate ต่อ Material แทน
เนื้อหาและภาพหน้าจอทั้งหมดยืนยันจากระบบจริงและโค้ดจริง (stone_slab_inventory module, Block) — เดินสดจริงบน eg-odoo19-ee วันที่ 17 ส.ค. 2026 (PO P00004 → BLK-26-0005) · ตรวจทานกับโค้ดล่าสุดอีกครั้ง 21 ส.ค. 2026
