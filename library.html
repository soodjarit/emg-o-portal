Management & Accounting
บริหารจัดการ, ต้นทุน, กำไร, บัญชี
1
กำไรรายโครงการ (Analytic Accounting)
ผูก Analytic Account เข้ากับ Bundle ครั้งเดียว — ต้นทุนและรายได้ทั้งสายแปะป้ายให้อัตโนมัติ จนเห็นกำไรจริงของแต่ละโครงการ
→
2
ใบรับรองหัก ณ ที่จ่าย (WHT Certificate)
พิมพ์แบบ 50 ทวิ ได้จากบิลผู้ขายโดยตรง — อัตราภาษีมีอยู่แล้วในระบบ ไม่ต้องตั้งค่าเพิ่ม
→
3
ต้นทุนหินก้อน + Landed Cost
รู้ต้นทุนจริงตั้งแต่วันนำเข้า ไม่ต้องรอตัดแผ่น — ค่าขนส่งกระจายตามสัดส่วนจริง และตรวจสอบย้อนกลับไปหาบิลจริงได้เสมอ

4

Golden Path Test Case
เดินเรื่องราวเดียวต่อเนื่องจนจบ full lifecycle ต่อ 1 จุดขาย/สวิตช์ ตามแนวคิด EG-321 — ไม่มี field-validation/error case เลย เขียนให้ non-technical user เดินตามได้เอง (แยกหมวดจาก QA/Test Cases ด้านบนซึ่งครอบคลุมฟีเจอร์/edge case ด้วย)
1
Golden Path — สวิตช์ Project (EG-321)
เดิมเรียก "Mode 4 (Sold-as-Project)" — ตามแนวคิด EG-321 ไม่ใช่จุดขายที่ 4 แต่เป็นสวิตช์ที่แปะกับใบสั่งขายจุดขายไหนก็ได้ (Block/Slab/FG) เพื่อเปิดการติดตามงานเป็น Task + เก็บเงินเป็นงวดผ่าน Milestone (ADR-021, ปรับกลไก Milestone ใหม่ ADR-069) สาธิตด้วยสินค้าบริการ "Protection Works" แต่สวิตช์นี้ใช้ได้กับสินค้าจริงประเภทไหนก็ได้ ไม่ต้องมี BOQ ก็เปิดใช้ได้ — เดินสดผ่าน Playwright (6 test cases)
17 ก.ย. 2026Build + Test ผ่านแล้ว
→
2
Golden Path — BOQ + Project ทำงานร่วมกัน (Self-Test)
2 สวิตช์ (BOQ / Project) พิสูจน์แล้วว่าเป็นอิสระต่อกันในเอกสารสวิตช์ทั้ง 2 ข้างต้น — เอกสารนี้สาธิตเมื่อใช้ร่วมกันแบบที่ลูกค้าจริงต้องการ: เริ่มจาก Cutting List จริงที่ลูกค้าส่งมา → ประเมินราคาเป็น BOQ → ออกใบเสนอราคา → เปิดสวิตช์ Project เพื่อติดตามงานเป็น Task ต่อ Zone พร้อม Milestone เก็บเงิน (13 test cases)
22 ก.ย. 2026ให้ผู้ใช้ทดสอบเอง — ยังไม่ได้รันจริงผ่านหน้าจอ

D3
ทำไมไม่ใช้ Standard/AVCO Cost ของ Odoo?
หินแต่ละก้อนราคาไม่เท่ากันจริง — เป็นปัญหา specific identification costing ที่ native costing method ของ Odoo ไม่รองรับ การเปลี่ยนไปใช้จะเป็นการเดินถอยหลังกลับไปเจอบั๊กที่เคยแก้แล้ว (2 ส.ค. 2026) ค่าแรงตัดที่จะเพิ่มเข้าไป แนะนำเพิ่มเป็น term ใหม่ในสูตร compute field เดิมแทน
20 ส.ค. 2026ยืนยันแล้ว — คงสถาปัตยกรรมเดิม
→
D4
CBM → ตัน: ความหนาแน่นตามประเภทหิน
ลูกค้าอยากตั้งค่าความหนาแน่น (ตัน/คิว) ไว้ที่ประเภทหิน แทนให้พนักงานคำนวณน้ำหนักเอง — เพิ่ม field ที่ Material + auto-fill Weight (Ton) ที่ Block (แก้ทับได้ถ้ามีชั่งจริง) ระหว่างคุยยังยืนยันด้วยว่า Landed Cost คงเฉลี่ยตามสัดส่วน CBM เดิม ไม่เปลี่ยนเป็นเฉลี่ยเท่ากันทุกก้อน ต่อยอดเพิ่มอีก 2 จุด: ซื้อเป็นตันตรงๆ ที่ PO และเช็คสต็อกเหลือเป็นตันได้เลย ทดสอบผ่านเบราว์เซอร์จริงครบทุกจุดแล้ว
