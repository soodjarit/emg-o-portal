EMG-O — คู่มือการใช้งาน

02 รับสินค้าเข้าคลัง

หมายเหตุหน้านี้พูดถึงการซื้อหินเท่านั้น
ถ้าซื้อของอย่างอื่นที่ไม่ใช่หิน (อุปกรณ์, วัสดุสิ้นเปลือง, บริการ ฯลฯ) ไม่ต้องผูก Block — ใช้ขั้นตอน Purchase มาตรฐานของ Odoo ตรงๆ ดู บทที่ 15: การจัดซื้อ
ข้อมูลศัพท์ "Block" (เดิมชื่อ "Bundle")
UI ปัจจุบันเรียกก้อนหิน 1 ก้อนว่า "Block" ทั้งหมด (เมนู, ฟอร์ม, list view) — model เบื้องหลัง (stone.bundle) และภาพหน้าจอบางรูปในบทนี้ยังเป็นเวอร์ชันก่อน rename อาจเห็นคำว่า "Bundle" ค้างอยู่ในภาพ ให้เข้าใจว่าคือหน้าจอเดียวกัน

ภาพรวม Flow

วิธีซื้อ + รับก้อนหินเข้าคลัง (ตัวอย่าง 1 ก้อน)

ก่อนสร้าง Block ต้องมี Purchase Order จริงที่ Confirm แล้ว ก่อนเสมอ (ดูเหตุผลใน callout ด้านล่าง):

1
Purchase → New → เลือก Vendor (ตัวอย่าง: Demo Supplier - Global Stone Quarry)
2
Add a product → เลือก Block Product ของวัสดุนั้น (เช่น "Rosa Portogallo Granite Block") → กรอก Quantity เป็นคิว (m³) ที่ซื้อจริง (ตัวอย่าง 5 m³) + ราคาต่อคิว (ตัวอย่าง 8,000/m³)
3
Save → Confirm Order — PO เปลี่ยนสถานะเป็น Purchase Order (ยืนยันแล้ว)
4
ไปที่ Stone Slab → Blocks → New → กรอก Block Code + เลือก Material → section "2. รับสต็อกก้อน (CBM)" จะโผล่มา
5
ช่อง Purchase Order Line — ระบบกรองให้เหลือเฉพาะ PO Line ของ Block Product วัสดุนี้ที่ Confirm แล้วเท่านั้น → เลือก PO ที่เพิ่งสร้าง
6
Supplier + Total CBM กรอกให้อัตโนมัติ จาก PO Line ที่เลือก (ตัวอย่าง Total CBM = 5.00 ตรงกับ PO) — เหลือแค่กรอก Thickness (M) เอง (ค่านี้ไม่ได้อยู่บน PO เพราะเป็นความหนาที่จะตัดแผ่น ไม่ใช่คุณสมบัติของก้อนดิบ)
7
เลือก Warehouse → Save — ระบบสร้าง Block Stock Lot ให้อัตโนมัติ และ Remaining CBM จะคำนวณสดตรงกับที่ซื้อจริงทันที

ซื้อหลายก้อนพร้อมกัน ขนาดไม่เท่ากัน (ตัวอย่าง 5 ก้อน)

ถ้าซื้อ material เดียวกันทีเดียวหลายก้อน (เช่น Rosa Portogallo Granite 5 ก้อน) ต้องออก PO เป็น 5 บรรทัดแยกกัน ไม่ใช่ 1 บรรทัดรวม quantity — เพราะระบบคิดต้นทุนต่อก้อนจาก purchase_line_id.price_subtotal ÷ total_cbm ของก้อนนั้นเจาะจง ถ้าเอา Block 2 ก้อนขึ้นไปไปผูกกับ PO Line เดียวกัน แต่ละก้อนจะถูกคิดต้นทุนเต็มยอดทั้งบรรทัดซ้ำกัน ไม่ใช่ยอดตามสัดส่วนจริง → ต้นทุนเพี้ยนทันที ระบบไม่มี guard กันเรื่องนี้ให้

1
Purchase → New → เลือก Vendor เดิม 1 ใบพอ (ไม่ต้องแยก PO ต่อก้อน)
2
Add a product เลือก "Rosa Portogallo Granite Block" ซ้ำ 5 บรรทัด กรอกแยกทีละบรรทัดตามขนาดจริงของแต่ละก้อน
บรรทัดQuantity (m³)ราคา/m³Subtotal

Block #25.18,00040,800

(ราคา/m³ ไม่จำเป็นต้องเท่ากันทุกก้อน ถ้าซัพพลายเออร์คิดราคาต่างกันตามคุณภาพ/ขนาดก้อน)

3
Save → Confirm Order — PO ใบเดียวมี 5 บรรทัด ยืนยันพร้อมกันหมด
4
สร้าง Block record 5 ตัว — Stone Slab → Blocks → New ทำ 5 รอบ แต่ละรอบเลือก Material เดิม → ช่อง Purchase Order Line จะโชว์ทั้ง 5 บรรทัดให้เลือก → เลือกให้ตรงก้อน ไม่ซ้ำกัน (Block #1 → บรรทัด qty 4.2, Block #2 → บรรทัด qty 5.1 ...) Total CBM จะ auto-fill ตามบรรทัดที่เลือก → กรอก Thickness เฉพาะก้อนนั้น → Save

ผลลัพธ์: ได้ Block 5 lot แยกกัน แต่ละก้อนมี Remaining CBM และ Cost/Sq.Mt. ถูกต้องตามราคาจริงของก้อนนั้น ไม่ปนกัน

คำเตือนขนาดเท่ากันทุกก้อนก็ยังต้องแยก PO Line เหมือนกัน
แม้ 5 ก้อนจะขนาดเท่ากันเป๊ะ (qty/ราคาซ้ำกันทุกบรรทัด) ก็ยังต้องออกเป็น 5 PO Line แยกกันอยู่ดี เพราะ field purchase_line_id บน Block เป็น Many2one ผูกได้ทีละ 1 บรรทัดเท่านั้น ไม่มีกลไกแบ่งสัดส่วนจาก 1 บรรทัดไปหลาย Block — กฎคือ 1 PO Line : 1 Block เสมอ ไม่ว่าขนาดจะเท่ากันหรือไม่
ข้อมูลระบบไม่มีช่องขนาด L×W×H — Quantity บน PO Line คือ CBM (m³) ตรงๆ
Block Product ตั้ง UoM เป็น Cubic Meter — ถ้าอยากรู้ปริมาตรต้องคำนวณ L×W×H เองก่อนกรอก Quantity ระบบไม่ track มิติจริงของก้อน (มีแค่ปริมาตรรวม) ถ้าต้องการบันทึกขนาดที่วัดจริงตอนรับของไว้เป็นข้อมูลอ้างอิง (ไม่กระทบ CBM/ต้นทุน) ใช้ช่อง Length (M) / Width (M) / Height (M) ในแท็บ "Block (Optional)" ของฟอร์ม Block (เพิ่มเข้าระบบ 2026-08-20)
สำเร็จระบบกันสต็อกซ้ำจากใบรับสินค้าอัตโนมัติแล้ว
สต็อกก้อนหิน/แผ่นหินทั้งหมดถูกจัดการโดยโมดูลนี้เอง ไม่ผ่านขั้นตอน "รับสินค้า" (Receipt) ปกติของ Odoo ระบบป้องกันสต็อกซ้ำอัตโนมัติ 2 ชั้น: (1) พอ Block ผูกกับ Purchase Order Line เสร็จ ใบรับสินค้าของ PO นั้นจะถูก ยกเลิกให้อัตโนมัติ — ไม่มีอะไรค้างให้กด Validate (2) ถ้ามีใครพยายามกด Validate ใบรับสินค้าของสินค้าหินอยู่ดี ระบบจะฟ้อง error ไม่ให้ผ่าน พนักงานไม่ต้องจำกฎนี้เองอีกต่อไป — ถ้าเห็นใบรับสินค้าของ PO หินขึ้นสถานะ Cancelled ไปเอง เป็นเรื่องปกติ ไม่ใช่บั๊ก

ภาพจริงจากการทดสอบบน production (ถ่ายก่อน rename UI เป็น "Block" — ฟอร์ม/เมนูในภาพจะโชว์คำว่า "Bundle" แต่เป็นหน้าเดียวกัน):

ถ้าพยายามกด Validate ใบรับสินค้าของสินค้าหินด้วยมือ (ก่อนหรือหลังมี Block ก็ตาม) ระบบจะฟ้อง error แบบนี้ทันที

ใบรับสินค้าเดียวกัน หลังจากสร้าง Block ผูกกับ Purchase Order Line นี้แล้ว — สถานะเปลี่ยนเป็น Cancelled ให้อัตโนมัติ

สร้าง Block (รายละเอียด field)

เมื่อสินค้าเข้าคลัง ให้สร้าง Block ใหม่ผ่านเมนู Stone Slab → Blocks → New

กรอกข้อมูลหลัก:

  • Block Code — เลข lot (ต่างจาก "Block Number" ที่เป็นเลขก้อนดั้งเดิมของเหมือง)
  • Material — เลือกชนิดหินจาก dropdown (ถ้ายังไม่มีในระบบ สร้างใหม่ได้จากช่องนี้เลย)
  • Supplier, Warehouse (กำหนดว่า Block นี้อยู่ WH ไหน/บริษัทไหน — EG หรือ ES)
  • ราคาขาย (Sales Price / Sq.Mt.)
คำเตือนข้อควรระวัง
การสร้าง Block ผ่านปุ่ม "New" ตรงๆ จะไม่ผูก Product อัตโนมัติ ถ้า Block ไม่ได้มาจากการรับสินค้าผ่าน PO จริง อาจทำให้ปุ่ม "Select Slabs" ในขั้นตอนขายหาแผ่นไม่เจอ — ให้ผ่าน flow รับสินค้าจริงผ่าน PO เสมอ ไม่ควรสร้าง Block ลอยๆ ในหน้างานจริง (ดู บทที่ 10: ข้อจำกัดที่ทราบ)

รับก้อนหิน (CBM) — เฉพาะ Material ที่มี Block Product

ถ้า Material นั้นมี Block Product ผูกอยู่ (material_id.product_id_block) ฟอร์ม Block จะบังคับให้กรอก section CBM เพิ่ม:

  • Total CBM — ปริมาตรก้อนหินทั้งหมดตามที่ซื้อจริง (m³)
  • Thickness (M) — ความหนาแผ่นมาตรฐานที่จะตัดจากก้อนนี้ (ใช้คำนวณหัก CBM อัตโนมัติตอนเพิ่มแผ่น)
  • Analytic Account — สำหรับ tag ต้นทุนแรงงาน/ค่าตัด

เมื่อ Save ระบบจะ:

1
สร้าง block_lot_id (lot แยกต่างหากจาก lot ของแผ่น — 1 lot ผูกได้แค่ 1 product เท่านั้น)
2
สร้าง stock.move รับก้อนหินเข้า location "Stone Available" ของ Warehouse นั้นให้อัตโนมัติ
3
Remaining CBM จะคำนวณสดจากสต็อกจริง (ไม่ใช่ field ธรรมดา) เพื่อกันปัญหาค่าค้าง (stale-store)

Container (ถ้ามีหลาย Block มาด้วยกัน 1 ตู้)

เมนู Stone Slab → Containers ใช้จัดกลุ่ม Block ที่มาด้วยกัน 1 container/shipment เดียวกัน — ใช้สำหรับกระจาย Landed Cost ตามสัดส่วน Sq.Mt. ของแต่ละ Block (ดู บทที่ 07: ต้นทุนสินค้า)
