30 Block — นิยาม แนวคิด ขั้นตอน และเงื่อนไข

อัปเดตล่าสุด: 14 ตุลาคม 2569 (2026-10-14) · ระบบ stone_slab_inventory เวอร์ชัน 19.0.2.109.23 · ภาพหน้าจอทั้งหมดมาจากการทดลองใช้งานจริงบนระบบทดสอบ

บทนี้อธิบายเรื่อง Block ตั้งแต่ว่า Block คืออะไร ทำไมระบบคิดแบบนี้ ไล่ไปทีละขั้นตั้งแต่ซื้อเข้ามาจนถึงตัดเป็นแผ่น และสุดท้ายคือ "ถ้าเกิดเหตุการณ์แบบนี้ ระบบจะทำอะไร" ทุกภาพเป็นหน้าจอที่ทดลองใช้งานจริง ไม่ใช่ภาพจำลอง และทุกเงื่อนไขในบทนี้ผ่านการทดลองแล้ว

1. Block คืออะไร

Block คือหินก้อนดิบหนึ่งก้อนที่ซื้อเข้ามา ยังไม่ได้ตัด เป็นวัตถุดิบต้นทางของงานทั้งสาย: Block → ตัดเป็น Slab (แผ่น) → ขายหรือผลิตเป็นสินค้าสำเร็จรูป

ส่วนว่าจะตัดหนากี่เซนติเมตร ผิวแบบไหน เป็นเรื่องของ แผ่นที่ตัดออกมา ก้อนเดียวกันจึงตัดเป็นแผ่นหนาไม่เท่ากันได้ ตามที่ลูกค้าแต่ละงานสั่ง

2. แนวคิดหลัก 5 ข้อ

  1. หนึ่งก้อนจริง = หนึ่ง Block ซื้อ 3 ก้อนต้องมี Block 3 เอกสาร ตัวเลข "จำนวน" ในใบสั่งซื้อ (PO) คือปริมาตรที่สั่งโดยประมาณ ไม่ใช่จำนวนก้อน
  2. ซื้อขายเป็นตัน แต่ระบบนับสต็อกเป็น ลบ.ม. ตัวเลขตันที่เห็นคำนวณจากปริมาตร ถ้าไม่ได้ชั่งจริงก็ใช้ค่านี้ แต่ถ้ากรอกตันตามใบส่งของตอนรับของ มูลค่าสต็อกและใบแจ้งหนี้ผู้ขายจะคิดจากตันนั้น × ราคาบาท/ตัน ตรงตามที่ซื้อจริง (ปรับปรุง 14 ตุลาคม 2569)
  3. ของเข้าคลังตอนกด Validate ที่ใบรับของ เหมือนการรับของใน Odoo ปกติ ไม่มีปุ่ม "สร้าง Block" แยกที่ต้องจำอีกแล้ว
  4. ส่วนที่ระบบเราเพิ่มเอง ทำงานต่อท้ายขั้นตอนปกติ คือช่องกว้าง/ยาว/สูง, การตั้งเลข Lot, และการสร้างเอกสาร Block ส่วนตัวเลขสต็อกและมูลค่าเป็นของ Odoo เอง
  5. ขนาดผิดแก้ได้ แต่ต้องมีเหตุผลและมีประวัติ ระบบไม่ให้แก้ตัวเลขสต็อกตรงๆ

4. ขั้นตอนทีละหน้าจอ

4.1 สั่งซื้อ (Purchase Order)

สร้างใบสั่งซื้อตามปกติ เลือกสินค้าที่เป็น Block ของหินชนิดนั้น ใส่จำนวน (ปริมาตรโดยประมาณ) และราคา ช่อง Qty (Ton) แสดงตันที่คำนวณให้ ตัวอย่างนี้สั่ง 4.00 ลบ.ม. = 10.80 ตัน

เคล็ดลับยังไม่ต้องรู้ขนาดจริงตอนสั่งซื้อ
ขนาดจริงวัดได้ตอนของมาถึง และกรอกที่ใบรับของ ไม่ต้องกลับมาแก้ใบสั่งซื้อ

4.2 รับของ (Receipt) — ขั้นตอนที่สำคัญที่สุด

เมื่อยืนยันใบสั่งซื้อ ระบบสร้างใบรับของให้ สังเกตแถบสีฟ้าด้านบนที่บอกว่าเป็น "รับ Block" และบอกวิธีกรอก

  1. กดคำว่า Details ที่แถวสินค้า จะเปิดหน้าต่าง Detailed Operations
  2. 1 แถว = 1 ก้อนจริง กรอก ยาว / กว้าง / สูง (เมตร) ของก้อนนั้น
  3. ถ้ามีหลายก้อน กด Add a line เพิ่มแถวทีละก้อน
  4. ช่อง Quantity ระบบคำนวณให้เอง (ล็อก พิมพ์ทับไม่ได้) และช่อง Qty (Ton) แสดงตันที่คำนวณจากขนาดของแต่ละก้อน ส่วนช่อง ตันตามใบส่งของ ใช้กรอกน้ำหนักที่ชั่งจริงตามใบส่งของ (เว้นว่างได้) ตัวอย่างนี้กรอก 5.200 และ 5.100 ตัน

ตัวอย่าง: ก้อนที่ 1 ขนาด 3.00 × 0.40 × 1.60 ม. = 1.92 ลบ.ม. (คำนวณ 5.18 ตัน, ใบส่งของ 5.200 ตัน) ก้อนที่ 2 ขนาด 2.80 × 0.45 × 1.50 ม. = 1.89 ลบ.ม. (คำนวณ 5.10 ตัน, ใบส่งของ 5.100 ตัน) รวม 3.81 ลบ.ม. / 10.300 ตัน

ระวังถ้ายังไม่กรอกขนาดแล้วกด Validate ระบบจะไม่ให้ผ่าน
ระบบแจ้งให้กรอก ยาว × กว้าง × สูง ของทุกก้อนก่อน นี่คือการป้องกันไม่ให้มี Block ที่ไม่รู้ขนาดเข้าคลัง

เมื่อกรอกครบแล้วกด Validate ถ้าปริมาตรที่รับจริงน้อยกว่าที่สั่ง (ตัวอย่างนี้สั่ง 4.00 รับ 3.81) Odoo จะถามเรื่อง Backorder:

ตัวเลือกใช้เมื่อ
Create Backorderผู้ขายจะส่งส่วนที่เหลือมาทีหลัง ระบบเปิดใบรับของใบใหม่ไว้รอ
No Backorderผู้ขายส่งครบแล้วเท่าที่จะส่ง ส่วนที่ขาดไม่มีมาอีก

หลัง Validate ระบบทำให้อัตโนมัติ และขึ้นข้อความยืนยันที่มุมจอทีละก้อน:

  • ตั้งเลข Lot ให้ทุกก้อน (เช่น BLK-26-0319-BLK)
  • ย้ายของจาก "Vendors - Stone" เข้า Stone Inventory / Stone Available
  • บันทึกมูลค่าตามราคาในใบสั่งซื้อ
  • สร้างเอกสาร Block ให้ทุกก้อน พร้อมขนาด ผู้ขาย และใบสั่งซื้อที่มา
หมายเหตุปลายทางของใบรับของ Block คือ Stone Inventory/Stone Available
ช่อง "Destination Location" ที่หัวใบรับของ (และช่อง Store To ในหน้าต่าง Details) แสดง Stone Inventory/Stone Available ตั้งแต่ตอนเปิดใบรับของ ไม่ใช่ EG01/Stock แล้ว (เวอร์ชันก่อนหน้าแสดง EG01/Stock ที่หัวเอกสาร)

4.3 Block ในคลัง

ไปที่เมนู Stone Slab → Blocks จะเห็น Block ทั้งหมดเป็นการ์ด ตัวเลขท้ายการ์ดคือปริมาตรและตันที่เหลือ (ปกติระบบซ่อน Block ที่ใช้หมดแล้ว)

เปิด Block จะเห็น การ์ดสรุป ด้านบนสุดของหน้า (อ่านอย่างเดียว) แบ่งเป็น 4 ช่อง: ขนาดก้อน (ยาว × กว้าง × สูง, ลบ.ม., ตัน) · คงเหลือ (ลบ.ม. และตัน) · ราคาขาย (บาท/ตัน เป็นตัวหลัก ใต้ลงมาคือ บาท/ลบ.ม. และบาท/ตร.ม. ของ Slab) · ผลการตัด (ถ้ายังไม่ตัดจะแสดงจำนวนแผ่นและ ตร.ม. โดยประมาณ) บรรทัดล่างของการ์ดคือต้นทุน (บาท/ตัน และบาท/ลบ.ม.) กับใบสั่งซื้อที่มา และมีป้ายสถานะ "ใช้ได้" / "ใช้หมดแล้ว" ข้างเลข Block

ใต้การ์ดเป็นแท็บ: ข้อมูล Block (ขั้นตอนที่ 1 รับ Block เข้าคลัง — คลัง, Material, บรรทัดใบสั่งซื้อ, ขนาด · ขั้นตอนที่ 2 ราคาขาย แก้ได้ทั้งบาท/ตัน, บาท/ลบ.ม., บาท/ตร.ม.) · ระบบเติม/คำนวณให้ (ดูเฉยๆ) · ข้อมูลเพิ่มเติม (ไม่บังคับ) · Slabs · Photos และแท็บ ประวัติแก้ขนาด จะโผล่เป็นแท็บสุดท้ายหลังมีการแก้ขนาดอย่างน้อย 1 ครั้ง

Block ที่เกิดจากใบรับของ ช่องขนาดจะถูกล็อก ถ้าต้องแก้ ให้ใช้ปุ่ม "แก้ขนาด" (หัวข้อ 4.5) ซึ่งอยู่มุมซ้ายบนของหน้า

4.4 เก็บเงิน — ใบแจ้งหนี้ผู้ขาย (Vendor Bill)

ใบสั่งซื้อจะแสดงช่อง Received เป็นปริมาตรที่รับจริง (3.81) ไม่ใช่ 4.00 ที่สั่ง

สร้างบิลที่ Accounting → Vendors → Bills → New เลือกผู้ขาย แล้วที่ช่อง Auto-Complete เลือกใบสั่งซื้อ ระบบดึงรายการมาให้ ตามที่รับจริง และเขียนเป็นตัน ในราคาบาท/ตันตามใบสั่งซื้อ (หน่วยในบิลเป็น "ตัน")

ตัวอย่าง: รับตามใบส่งของ 5.200 + 5.100 = 10.300 ตัน × 10,000 บาท/ตัน = 103,000 บาท ตรงกับใบแจ้งหนี้ของผู้ขาย (ไม่ใช่ 4.00 ลบ.ม. ที่สั่ง ซึ่งจะเป็น 108,000 บาท) ในบิล ช่อง Quantity เป็นตัน (10.300) และ Price เป็นบาทต่อตัน (10,000)

ปรับปรุง 14 ต.ค. 2569ราคาที่ซื้อมา = ราคาในบิล ไม่คลาดเพราะปัดเศษ ลบ.ม.
เดิมบิลถูกแปลงเป็น ลบ.ม. (ปัด 2 ตำแหน่ง) ทำให้ยอดบิลคลาดจากใบส่งของเล็กน้อย เช่น 100,000 กลายเป็น 99,9xx ตอนนี้บิลและใบลดหนี้ (Credit Note) เขียนเป็นตัน (ทศนิยม 3 ตำแหน่ง) ยอดจึงเท่ากับตันที่รับ × ราคาต่อตันเสมอ ใช้ได้เมื่อ Block มี "ตันตามใบส่งของ" ที่กรอกตอนรับของ (ถ้าไม่มี ระบบยังออกบิลเป็น ลบ.ม. แบบเดิม) ช่องจำนวนทุกบรรทัดในบิล/ใบแจ้งหนี้แสดงทศนิยม 3 ตำแหน่ง
ข้อมูลต้นทุน Block คิดแยกตามก้อน
Block ทุกก้อนมี Lot ของตัวเอง และมูลค่าถูกเก็บตาม Lot ต้นทุนของแต่ละก้อนจึงมาจากราคาที่ซื้อก้อนนั้นจริง ไม่ปนกับก้อนที่ซื้อคนละราคา (เดิม Odoo ใช้วิธีเข้าก่อนออกก่อน (FIFO) ต่อสินค้า ทำให้ตัด ขาย หรือคืน Block ราคา 27,000 ไปหยิบต้นทุนของ Block เก่าราคา 16,200)

4.5 แก้ขนาด Block (ถ้าวัดผิด)

เปิดหน้า Block กดปุ่ม แก้ขนาด (มุมซ้ายบน) ปุ่มนี้ใช้ได้เฉพาะผู้มีสิทธิ์ Inventory Administrator หน้าต่างจะแสดงขนาดเดิมและขนาดใหม่เทียบกัน

ต้องระบุเหตุผลทุกครั้ง ถ้าเว้นว่าง ระบบแจ้ง "Missing required fields" และไม่บันทึก

เมื่อกดแก้ขนาด ระบบจะ:

  • เปลี่ยนขนาดและปริมาตรของ Block
  • ปรับสต็อกส่วนต่างให้ (ตัวอย่างนี้สูง 1.60 → 1.50 ปริมาตร 1.92 → 1.80 ปรับลด 0.12)
  • บันทึกประวัติ ใครแก้ เมื่อไร จากอะไรเป็นอะไร เพราะอะไร ที่แท็บ ประวัติแก้ขนาด (แท็บสุดท้ายของหน้า Block) หลังแก้ ตัน/คงเหลือ/จำนวนแผ่นที่คาดว่าจะตัดได้ ในการ์ดสรุปจะปรับตามขนาดใหม่ทันที
เงื่อนไขผล
ไม่ใช่ Inventory Administratorไม่เห็นปุ่ม ใช้ไม่ได้
ไม่ใส่เหตุผลบันทึกไม่ได้
ปริมาตรใหม่น้อยกว่าที่ตัดไปแล้วไม่อนุญาต
ปริมาตรลดลง แต่ของใน Stone Available ไม่พอจะหักส่วนต่างไม่อนุญาต ต้องเคลียร์ของที่ค้างที่อื่นก่อน
เงื่อนไขครบแก้ได้ ปรับสต็อกส่วนต่าง และบันทึกประวัติ

4.6 สั่งตัดเป็นแผ่น (Cut Order)

ใบตัดคือใบ Manufacturing Order ชนิด "ตัด Slab จาก Block" สร้างที่ Manufacturing → Manufacturing Orders → New แล้วเลือก Block ที่จะตัด ในขั้นตอนที่ 1 ระบบแสดงการ์ดสรุป (Block ที่ตัด, เหลือกี่ ลบ.ม., ขนาดเป้าหมาย, ความหนา, จำนวนแผ่นและ ตร.ม. ที่คาดว่าจะได้) และข้อความสีเขียว/เหลืองบอกว่า Block พอหรือไม่ จากนั้นกรอกตามขั้นตอน: ขั้นตอนที่ 2 ขนาดแผ่น L × H, ผิวหน้า (Finish) และความหนา (ถ้าเลือก Other ให้กรอกเป็น ซม.) · ขั้นตอนที่ 3 ผูกกับบรรทัดใบขาย (SO) หรือ ระบุเหตุผลกรณีไม่มี SO ถ้าไม่เลือกอย่างใดอย่างหนึ่ง กด Confirm ไม่ผ่าน ใช้ปริมาตรจาก Block ใน Stone Available เมื่อกด Complete Cut ได้ Slab ตามจำนวนแผ่นจริง ที่เหลือของ Block ลดลงตามที่ตัด แผนแผ่นที่ตัดอยู่ที่แท็บ Slab ที่ตัดได้ (แผน/จริง) (ปุ่ม "สร้างแผนใหม่" คำนวณจากขนาดที่ระบุ)

ต้นทุนตอนตัด: ต้นทุนของ Block ถูกถ่ายไปที่ Slab เฉพาะส่วนที่ตัดใช้จริง (ปริมาตรแผ่น ÷ (1 − % สูญเสีย)) แบ่งให้แต่ละแผ่นตามปริมาตร ส่วนที่ยังไม่ได้ตัดเหลือเป็น Block ในคลังพร้อมต้นทุนส่วนที่เหลือ ในบัญชีเกิด 2 รายการ (ย้ายไปผลิต / รับ Slab เข้าคลัง) ลงบัญชีสินค้าคงคลังเดียวกัน ยอดสุทธิเป็น 0 ไม่กระทบกำไรขาดทุน (รอนักบัญชียืนยันว่าจะใช้บัญชีเดียวกันสำหรับ Block และ Slab หรือแยกบัญชี)

ระบบมีแถบเตือนสีเหลืองเมื่อ ขนาดแผ่นที่ตั้งไว้ไม่พอดีกับ Block และตั้งแต่ 8 ตุลาคม 2569 ไม่ใช่แค่เตือน — ใบตัดที่ขนาดแผนไม่พอดีกับ Block จะกด Confirm หรือ Complete Cut ไม่ผ่าน (ข้อความ "ตัดจริงไม่ได้") จนกว่าจะแก้แผนที่แท็บ Slab ที่ตัดได้ มี 2 กรณี:

(ก) ความหนารวมของแผ่นทั้งหมดเกินความกว้างของ Block

(ข) ความยาวหรือความสูงของแผ่นใหญ่กว่า Block

ข้อมูลใบตัดใช้ประเภทปฏิบัติการ "Stone Cutting"
ระบบตั้งให้อัตโนมัติ เพื่อให้หักปริมาตรจาก Stone Available ถูกที่ (เคยพบว่าตัดจากคลังผิดที่ในใบตัดเก่าก่อนแก้ไข)

4.7 คืน Block ให้ผู้ขาย

ใบรับของที่ Validate แล้ว ยกเลิกไม่ได้ ถ้ากดยกเลิก ระบบแจ้งว่า "You cannot cancel a stock move that has been set to Done" ให้ใช้การ คืนของ (Return) แทน:

  1. เปิดใบรับของที่ Done กดปุ่ม Return
  2. กด Return All (ถ้าคืนทั้งหมด) หน้าต่างเริ่มต้นแสดง 0.00 ซึ่งเป็นปกติของ Odoo
  3. ระบบสร้างใบคืน (EG01/OUT/…) และ จองก้อนเดิมให้เอง ใบคืนขึ้นสถานะ Ready กด Validate ได้เลย (ถ้าอยากตรวจ กด Details จะเห็นแถวของ Block ก้อนเดิมพร้อมปริมาตร)

ใบคืน Block เลือกได้เฉพาะ Block ของใบรับของเดิม เท่านั้น: ในหน้า Details ถ้ากด Add a line รายการจะมีแต่ก้อนของใบรับของนั้น และถ้าพยายามใส่ Lot ของก้อนอื่น ระบบแจ้งว่าคืนได้เฉพาะ Block ของใบรับของเดิม (ปรับปรุง 11 ตุลาคม 2569)

ผลลัพธ์: สต็อกถูกหักออกจาก Stone Available, มูลค่าที่คืนเท่ากับมูลค่าที่รับเข้ามาของก้อนนั้นเอง (ไม่ไปหยิบราคาของ Block ก้อนอื่น — ปรับปรุง 14 ตุลาคม 2569), ช่อง Received ในใบสั่งซื้อกลับเป็น 0 และ เอกสาร Block ยังอยู่เป็นประวัติ แต่คงเหลือ 0.00

ระวังคืนได้เฉพาะส่วนที่ยังอยู่ในคลัง
ถ้า Block ถูกตัดไปบางส่วนแล้ว ส่วนที่ตัดไปแล้วคืนผู้ขายไม่ได้ (เป็นไปตามหลักของ Odoo) คืนได้เฉพาะส่วนที่เหลือเป็น Block ในคลัง กรณีนี้ยังไม่ได้ทดลองบนหน้าจอจริง หากเจอให้แจ้งทีมดูแลระบบ ส่วนใบลดหนี้ผู้ขายของการคืน ระบบเขียนเป็นตันตามใบส่งของของใบรับของนั้น (หักสัดส่วนที่คืน)

5. สรุปเงื่อนไขทั้งหมด

5.1 ตอนรับของ

สถานการณ์ระบบทำอย่างไร
กด Validate โดยไม่กรอก ยาว/กว้าง/สูงไม่ให้ผ่าน แจ้งให้กรอกก่อน
เพิ่มแถวก้อนที่ 2, 3 ในหน้า Detailed Operationsรับครบทุกก้อนที่กรอกขนาดไว้ (ทดลองแล้ว ได้ Block 2 เอกสารจากแถว 2 แถว)
รับน้อยกว่าที่สั่งOdoo ถามสร้าง Backorder หรือไม่ ตามหัวข้อ 4.2
พิมพ์ทับช่อง Quantity ของ Blockทำไม่ได้ ช่องล็อก ใช้ปริมาตรจากขนาดเสมอ
ใบรับของมีสินค้าอื่นปนกฎ Block ใช้กับแถว Block เท่านั้น แถวอื่นทำตามเดิม
รับสินค้าที่เป็น Slab (แผ่น) ผ่านใบสั่งซื้อยังกันไว้ตามกฎเดิม Slab ไม่รับผ่านทางนี้

5.2 ขนาด ปริมาตร น้ำหนัก

หัวข้อกฎ
ปริมาตรกว้าง × ยาว × สูง เสมอ สต็อกเก็บทศนิยม 2 ตำแหน่ง (เป็นธรรมชาติของ Odoo) ขนาดแต่ละด้านเก็บ 3 ตำแหน่ง
ตันปริมาตร × ความหนาแน่นของหิน ระบบกรอกให้ตอนรับของ ถ้าชั่งจริงไม่ตรงให้แก้ที่หน้า Block
ราคาซื้อ / มูลค่าสต็อกถ้ากรอก "ตันตามใบส่งของ" ตอนรับของ: มูลค่า = ตันตามใบส่งของ × ราคาบาท/ตันในใบสั่งซื้อ (ตันเก็บทศนิยม 3 ตำแหน่ง) ถ้าไม่กรอก: ต้นทุนต่อ ลบ.ม. = ยอดเงินในใบสั่งซื้อ ÷ ปริมาตรที่สั่ง ต้นทุนเก็บแยกตามเลข Lot ของแต่ละก้อน

5.3 หลายบริษัท

ทดลองรับ Block ทั้งบริษัท Empire Granite (EG) และ Empire Stone (ES) บนระบบทดสอบ ผลคือ แต่ละบริษัทเข้าคลังของบริษัทตัวเอง (Stone Available ของคลังนั้น) Block สังกัดบริษัทที่รับ และบิลตามที่รับจริงเหมือนกัน

หมายเหตุ: การซ่อนปุ่มสำหรับผู้ที่ไม่ใช่ Inventory Administrator ตั้งตามที่ออกแบบ ยังไม่ได้ลองล็อกอินด้วยผู้ใช้ระดับต่ำกว่าเพื่อยืนยันบนหน้าจอ

6. สิ่งที่เปลี่ยนจากเดิม

เดิมตอนนี้
ต้องกดปุ่มสร้าง Block แยก (ผู้ใช้มักลืม)Validate ใบรับของ Block ก็เกิดให้เอง
ต้องยกเลิกใบรับของ แล้วสร้าง Block เองไม่ต้องยกเลิกอีก
กรอกขนาดที่หน้า Blockกรอกที่ใบรับของ ตอนวัดจริง
แก้ขนาดได้ตรงๆ ไม่มีบันทึกแก้ผ่านปุ่ม มีเหตุผลและประวัติ
บิลผู้ขายดึงตามที่สั่งตามที่รับจริง และเขียนเป็นตัน (ตรงกับใบแจ้งหนี้ผู้ขาย)
ต้นทุน Block ปนกันระหว่างก้อนที่ราคาต่างกัน (FIFO ต่อสินค้า)แยกตาม Lot ของแต่ละก้อน ตัด/ขาย/คืนใช้ต้นทุนของก้อนนั้น
คืน Block ให้ผู้ขายใช้ต้นทุนของ Block อื่นคืนที่มูลค่าตามใบรับของเดิม
ยังใช้ทางเดิมBlock ที่สร้างเองโดยไม่มีใบสั่งซื้อ, Container, และการรับ Slab
ส่วนเหล่านี้ไม่ได้เปลี่ยน ยังใช้วิธีเดิมตามบทที่ 02 และ 15 (บางส่วนของสองบทนั้นที่พูดถึงปุ่มสร้าง Block จากใบสั่งซื้อ ให้ถือบทนี้เป็นหลักสำหรับการซื้อ Block)

7. คำถามที่พบบ่อย

ใส่ 3 ในช่องจำนวนของใบสั่งซื้อ คือซื้อ 3 ก้อนหรือเปล่า
ไม่ใช่ครับ คือปริมาตร 3 ลบ.ม. โดยประมาณ จำนวนก้อนมาจากจำนวนแถวที่กรอกที่ใบรับของ

กรอกขนาดผิดแล้ว Validate ไปแล้ว ทำอย่างไร
ใช้ปุ่ม "แก้ขนาด" ที่หน้า Block (หัวข้อ 4.5) ต้องเป็น Inventory Administrator และระบุเหตุผล

รับของแล้วผู้ขายส่งผิด อยากคืนทั้งก้อน
ใช้ Return ที่ใบรับของ (หัวข้อ 4.7) Block จะคงเหลือ 0 และยังเก็บเป็นประวัติ

ทำไมน้ำหนักตันไม่ตรงกับที่ชั่ง
ตันที่เห็นคำนวณจากปริมาตร × ความหนาแน่น ถ้าชั่งจริงได้ต่างจากนี้ ให้กรอก "ตันตามใบส่งของ" ที่ใบรับของ มูลค่าและบิลจะคิดตามตันนี้ (การแก้ช่อง Weight (Ton) ที่หน้า Block ไม่ทำให้มูลค่าที่รับเข้าไปแล้วเปลี่ยน)

บิลผู้ขายต้องจ่ายตามตันหรือ ลบ.ม.
ตามตัน บิลเขียนเป็นตัน × ราคาบาท/ตัน ตามใบส่งของ (ตั้งแต่ 14 ตุลาคม 2569) ระบบนับสต็อกเป็น ลบ.ม. ภายใน แต่ยอดเงินในบิลไม่ขึ้นกับการปัดเศษ ลบ.ม.

8. ข้อจำกัดที่ทราบ

  • คืน Block ที่ถูกตัดบางส่วนไปแล้ว ยังไม่ได้ทดลองบนหน้าจอจริง
  • Block ที่ไม่มี "ตันตามใบส่งของ" และการคืนที่ย้อนไปหาตันของใบรับของไม่ได้ ยังออกบิล/ใบลดหนี้เป็น ลบ.ม. แบบเดิม (อาจคลาดเล็กน้อยจากการปัดเศษ)
  • รอนักบัญชียืนยัน: ใช้บัญชีสินค้าคงคลังเดียวกันสำหรับ Block และ Slab หรือแยกบัญชี, และยืนยันการเขียนบิล Block เป็นตัน
  • ใบตัดเก่าบางใบ (ก่อน 4 ตุลาคม 2569) หักสต็อกจากที่ผิด ทีมดูแลระบบจะทยอยตรวจแก้
  • สิทธิ์ผู้ใช้ระดับต่ำ ยังไม่ได้ลองล็อกอินยืนยันบนหน้าจอ
  • บิลของใบสั่งซื้อที่เปิดก่อน 4 ตุลาคม 2569 อาจยังตั้งค่าเป็น "ตามที่สั่ง" ให้ตรวจก่อน Confirm
