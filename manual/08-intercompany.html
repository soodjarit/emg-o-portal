08 ขายข้ามบริษัท (EG↔ES)

Empire Stone มี 2 บริษัทแยกกัน (Company EG และ Company ES) แต่ละบริษัทมี Warehouse ของตัวเอง (WH-EG, WH-ES) เมื่อพนักงานฝั่ง EG เปิด SO แล้วเลือกแผ่นที่อยู่ในสต็อกของ ES (หรือกลับกัน) ระบบจะจัดการ intercompany trade ให้อัตโนมัติทั้งหมด โดยพนักงานไม่ต้องทำอะไรเพิ่ม

สำเร็จ✅ Validated live end-to-end (2026-07-22)
ทดสอบจริงผ่านหน้าเว็บทั้งกระบวนการ (ไม่ใช่แค่ odoo shell): สร้างสต็อกใหม่จริงฝั่ง ES ผ่าน PO → เปิด SO ฝั่ง EG → Select Slabs เห็นสต็อก ES ปนมาด้วยจริง → Confirm SO → Internal SO [S54390](https://odoo19-mbxai.mx-erp.com/odoo/sales/60136)/PO P00055 สร้างอัตโนมัติ ราคาตรงสูตร markup 10% เป๊ะ (cost 13,714.29 × 1.10 = 15,085.71, รวม VAT 16,141.71) → Delivery Order ES (ESWH/OUT/00010) ตัดตรงจาก Stone Hold → Customers แบบ drop-ship จริง → Draft Invoice/Bill ออกอัตโนมัติ → ขึ้นการ์ดใหม่ใน Intercompany Reconciliation dashboard ครบ ระหว่างทางเจอบั๊กจริง 1 ตัว แก้แล้ว (ดูหัวข้อด้านล่าง)

วิธีขาย (คลิปสาธิต Flow การขายข้ามบริษัทจริง)

คลิปสาธิตประกอบ (ไม่ได้แนบในหน้านี้ — ดูจากทีมงานได้)

*คลิปนี้คือ session พนักงาน EG ปกติ (ไม่ได้ติ๊ก company ES ไว้ในตัวสลับบริษัท) เปิด SO ใหม่ → เลือกสินค้าหิน → Select Slabs เห็นสต็อก ES ปนมาให้เลือก → Confirm Selection → Confirm SO ทั้งใบ → เปิดดู Delivery ที่ตัดตรงจากคลัง ES → ไปดู Intercompany Reconciliation dashboard เห็นแถวใหม่ขึ้นจริง ทั้งหมดในเทคเดียวไม่มีตัดต่อ (บันทึกหลังแก้บั๊ก sudo() ด้านล่างแล้ว)*

สรุปขั้นตอนที่ระบบทำให้อัตโนมัติ:

1
พนักงาน EG เปิด SO ให้ลูกค้า แล้วเลือกแผ่นผ่าน "Select Slabs" Wizard ตามปกติ (ดู บทที่ 04: ขายเป็นแผ่น (ไม่แปรรูป)) — wizard จะโชว์แผ่น Available ทั้งจาก WH-EG และ WH-ES ให้เลือกรวมกัน

*สต็อก ES-B-0001 (ฝั่ง ES) ขึ้นในลิสต์ให้เลือกจริง ทั้งที่ SO นี้เปิดอยู่ใต้ Company EG*

2
ถ้าเลือกแผ่นที่อยู่ WH-ES ทั้งที่ SO เปิดอยู่ใต้ Company EG ระบบจะตรวจพบว่า Company ของ Block (ES) ไม่ตรงกับ Company ของ SO (EG)
3
ระบบสร้างเอกสารภายในให้อัตโนมัติ:
  • Internal SO (ES ขายให้ EG) ราคา = cost_sqmt × 1.10 (markup 10% ตาม config res.company.stone_intercompany_markup_pct)
  • Internal PO คู่กัน (EG ซื้อจาก ES) — auto-confirm ให้เลย
4
ใช้วิธี Drop-ship: Delivery Order จริงจะถูกส่งตรงจาก WH-ES ไปยังที่อยู่ลูกค้าปลายทางเลย ไม่มีการย้ายสต็อกเข้า WH-EG จริง (เพื่อไม่ให้กระทบ inventory integrity ของบริษัทผู้ขาย — ไม่ใช้ native Odoo Dropship mechanism)

*SO S54389 confirm สำเร็จ ไม่มี error — smart button "Delivery 1" คือใบส่งของจริงที่ตัดตรงจากคลัง ES*

5
SO เดิม (EG → ลูกค้า) จะ invoice ลูกค้าตามราคาขายเต็มตามปกติ ส่วน Internal SO/PO ที่สร้างอัตโนมัติใช้สำหรับการบันทึกบัญชี intercompany เท่านั้น
6
(ใหม่ 2026-07-07, ADR-014) ทันทีที่ Internal SO/PO confirm ระบบจะออก draft invoice (ฝั่ง ES ขาย) และ draft vendor bill (ฝั่ง EG ซื้อ) ให้อัตโนมัติทันที — ยังไม่ post เข้าบัญชี ต้องให้ฝ่ายบัญชีเข้าไปตรวจตัวเลข/วันที่แล้ว post เองอีกที (เจตนาให้ตรวจก่อนเสมอ ไม่ auto-post)
7
(ใหม่ 2026-07-07, ADR-014 Phase 2) ดูสรุปทุกรายการซื้อขายข้ามบริษัทได้ที่เมนู Stone Slab → Intercompany Reconciliation — การ์ดแยกตามทิศทาง (เช่น ES → EG) พร้อม badge "รอตรวจสอบ"/"Post แล้ว" คลิกการ์ดเพื่อดูรายการ แล้วคลิกที่ invoice/bill ในตารางเพื่อเปิดเอกสารจริงไปตรวจ/post ได้ทันที

*แถวใหม่ S54389 → S54390 → P00055 ขึ้นในตารางจริง cross-check ยอด 16,141.71 ตรงกับ Internal SO/PO/Invoice/Bill ทุกจุด*

🐛 บั๊กที่พบ+แก้ระหว่าง validate (2026-07-22)

ปุ่ม Confirm Selection ใน Select Slabs wizard ขึ้น Access Error ทันทีที่ hold แผ่นข้ามบริษัท — ทดสอบจริงครั้งแรกด้วย session พนักงาน EG ปกติ (ไม่ได้ติ๊ก company ES ไว้ใน company selector มุมขวาบน ซึ่งเป็นสภาพจริงของพนักงานทั่วไปที่ไม่เคยต้องสลับบริษัทเอง) พบ error ทันที:

> Sorry, emg_demo doesn't have 'read' access to: Warehouse (stock.warehouse)

Root cause: stone.slab.write() เรียก _stock_move_status_change() → _get_bucket_location() ทุกครั้งที่ status เปลี่ยน (เช่นตอน hold) ซึ่งอ่าน bundle.warehouse_id ของ ES โดยไม่ได้ sudo() — เมธอดนี้อยู่ใน write() กลาง ซึ่งเป็น code path ที่ทุกโหมดการขาย (1-4) ใช้ร่วมกันทั้งหมด ไม่ใช่แค่ Select Slabs

แก้แล้ว: เพิ่ม .sudo() ตรงจุดเรียก _stock_move_status_change() ใน write() (commit 58fa4df บน project/emg-o) — ตรรกะเดียวกับที่ใช้แก้ปัญหาคล้ายกันมาก่อนแล้วใน _compute_stone_slab_count/action_cancel/_process_stone_intercompany_trade re-test ผ่านทั้ง odoo shell (จำลอง session พนักงาน EG เป๊ะๆ) และผ่านหน้าเว็บจริงซ้ำจนยืนยันว่า hold สำเร็จ ไม่มี error แล้ว

คำเตือนยังไม่ได้ไล่ทดสอบ Mode 1/3/4 ข้ามบริษัทซ้ำ
บั๊กนี้อยู่ใน write() กลางที่ทุกโหมดใช้ร่วมกัน จึงมีโอกาสสูงว่า Mode 1 (Select Block)/Mode 3 (Cut to Order)/Mode 4 (Project) ก็เจอ error เดียวกันถ้าเคยลองข้ามบริษัทมาก่อนหน้านี้ — Session นี้ validate เจาะจงแค่เส้นทาง Select Slabs (โหมดแผ่นสำเร็จรูป) เท่านั้น ยังไม่ได้ไล่ทดสอบโหมดอื่นซ้ำหลังแก้
หมายเหตุข้อจำกัดที่ทราบอยู่แล้ว
- Delivery เดิมของฝั่งขาย (ก่อนสลับเป็น drop-ship) จะถูก cancel ตรงๆ ไม่ผ่าน backorder wizard ปกติ - Fiscal Position ระหว่าง EG↔ES ไม่ได้ทำ เพราะทั้งคู่เป็นบริษัทไทย VAT 7% เท่ากัน - Dashboard เฉพาะแสดงรายการที่เกิดผ่านระบบนี้เท่านั้น — เจอรายการเก่าจาก 2026-07-01 (ก่อนมี ADR-014) ที่ไม่เคยมี invoice/bill เลย ต้องให้ฝ่ายบัญชีตรวจเองว่าจะย้อนออกเอกสารให้หรือไม่
