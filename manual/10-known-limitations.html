10 ข้อจำกัดและบั๊กที่ทราบ

รวมทุกจุดที่รู้อยู่แล้วว่ายังไม่สมบูรณ์ ณ วันที่ 2026-07-06 (Session 25) — อัปเดตหน้านี้ทุกครั้งที่มีจุดใหม่หรือแก้ไปแล้ว

ยังไม่แก้ / เป็น known gap

  • สร้าง Block ผ่านปุ่ม "New" ตรงๆ ไม่ผูก Product อัตโนมัติ — ต้องรับสินค้าผ่าน PO จริงเสมอ (ดู บทที่ 02: รับสินค้าเข้าคลัง)
  • ยังไม่มีเครื่องสแกนจริง สำหรับยืนยัน Serial ตอนส่งของ — ตอนนี้พนักงานเลือกจาก dropdown แทน (ดู บทที่ 06: ส่งของและยืนยันการรับ)
  • VOLTA AV / VIVO Sport มี warehouse ขั้นต่ำที่สร้างไว้แค่ให้ module อื่นติดตั้งผ่าน — ยังไม่ตรวจสอบว่ากระทบ flow ของ 2 บริษัทนี้เองหรือไม่
  • รายการซื้อขายข้ามบริษัทเก่าก่อน ADR-014 (2026-07-01, S54251/P00003) ไม่มี invoice/bill — Intercompany Reconciliation dashboard เจอเข้าให้ตั้งแต่ครั้งแรกที่เปิดใช้ ยังไม่ได้ตัดสินใจว่าจะย้อนออกเอกสารให้หรือปล่อยไว้ (ดู บทที่ 08: ขายข้ามบริษัท)
  • Fabrication ข้ามบริษัท (แผ่นอยู่ ES แต่จะเจาะที่ EG) ตอนนี้บล็อกแค่ด้วย view domain ไม่มี hard constraint ระดับ server — ยังไม่เจอเคสจริงที่ต้องใช้
  • eCommerce Catalog: มีแค่บางแผ่นกรอกราคาขายจริงแล้ว แผ่นอื่นโชว์ ฿0 (ดู บทที่ 09: eCommerce Catalog)
  • Slabware Inbound API (ให้ระบบภายนอกส่งข้อมูล material/block/slab เข้ามาทางเดียว) — ยืนยันแล้วว่าไม่ชนกับของที่มีอยู่ แต่รอ payload spec จาก vendor ก่อนถึงจะออกแบบได้
  • Block Kanban (Phase 2) ยังพอมีจุดที่ปรับปรุงเพิ่มได้ — nice-to-have ไม่ block งาน
  • Scan Station (บทที่ 11: เช็คสต็อก Scan Station) ยังไม่มีเครื่องสแกนจริงมาทดสอบ (build+verify ผ่าน HTTP จำลองแล้วเท่านั้นทั้ง 2 โหมด), ยังไม่มีหน้าจัดการรายการ "หาย/เกิน" ต่อจาก Excel ที่ export ออกมา
  • ตั้งราคาแผ่นเองในบรรทัดใบขาย แล้วค่อยกด "Select Slabs" ทีหลัง → ราคาที่ตั้งไว้จะรีเซ็ตกลับเป็นราคามาตรฐานของสินค้า (พฤติกรรมของ Odoo เอง ไม่ใช่บั๊กของโมดูลนี้) — ต้องตั้งราคาเองหลังเลือกแผ่นเสร็จแล้วเท่านั้น (ดู บทที่ 12: กำไรรายโครงการ)
  • เมนู "Analytic Items" (ดูรายละเอียดต้นทุน/รายได้แยกโครงการ) ไม่ขึ้นในแถบเมนูของผู้ใช้ทั่วไป เพราะอยู่ใต้กลุ่มสิทธิ์ "Show Accounting Features" — ต้องเปิด URL ตรง (/odoo/action-154) หรือให้ผู้ดูแลระบบเปิดสิทธิ์เพิ่ม (ดู บทที่ 12: กำไรรายโครงการ)

แก้ไปแล้ว (Session 25, 2026-07-05/06)

  • Select Slabs wizard เปิดซ้ำแล้วว่างเปล่า — แก้แล้ว (pre-populate + widen domain)
  • ชื่อแผ่นแสดงเป็น stone.slab,15 (technical) — แก้แล้ว (display_name ใหม่)
  • เลข Slab No. ซ้ำกันในบันเดิลเดียวกัน — แก้แล้ว (self-heal auto-number)
  • Lot/Serial Number มองไม่เห็นใน Repair Order/Delivery Order — แก้แล้ว (permission setting)
  • OwlError ตอนกด "Moves"/"Details" บน Delivery Order — แก้แล้ว (column_invisible bug)

Bug pattern ที่ควรเช็คซ้ำเสมอเมื่อเพิ่ม feature ใหม่

  • Compute field ใหม่ที่จะใช้ใน domain search() ต้องมี store=True เสมอ
  • stock.lot ผูกได้แค่ 1 product เท่านั้น — ห้ามให้ 2 field คนละ product resolve ไป lot เดียวกัน
  • การสร้าง record ผ่าน inline list ของ Odoo web client อาจ save เป็นหลายจังหวะ (create/write แยกกัน) — logic ที่ทำงานตอน create() อย่างเดียวอาจไม่ครบ ต้องทำเป็น idempotent guard เรียกทั้ง create() และ write()
  • unlink() ไม่ reverse stock move ที่สร้างไว้ตอน create() เอง — ต้องคืนสต็อกด้วยมือก่อนลบเสมอ
  • column_invisible ใน list view ต้องอ้างอิงแค่ context/ค่าคงที่ ห้ามอ้าง field ระดับ record (ใช้ invisible แทนสำหรับกรณีนั้น)
  • Field ที่ default ไปตาม env.company เงียบๆ (เช่น location, website, ir.sequence) เสี่ยงผูกผิดบริษัทบน instance ที่มีหลายบริษัทร่วมกัน — ต้องเช็ค/ระบุ company_id ให้ชัดเจนเสมอ และทดสอบด้วย user จริงที่ไม่ใช่ admin ก่อนเชื่อว่าใช้ได้ (เจอกับ ir.sequence ของ Scan Station Session 28 — next_by_code() คืนค่า False เงียบๆ ไม่ error เลยถ้า company ไม่ตรง)
  • ไฟล์ static (JS/CSS) ของหน้า /stone-scan ผ่าน Cloudflare cache สูงสุด 7 วัน (cache-control: public, max-age=604800) — แก้โค้ดแล้ว deploy จริง แต่ user ยังเห็นเวอร์ชันเก่าจนกว่าจะ hard refresh หรือ cache หมดอายุ ถ้าแก้ static asset ของหน้านี้อีกในอนาคต ต้องเพิ่มเลข ?v= ต่อท้าย URL ใน template ทุกครั้ง ไม่งั้นจะดูเหมือน "deploy ไม่ขึ้น" ทั้งที่จริงๆ ขึ้นแล้วบน server

แก้ไปแล้ว (Session 28, 2026-07-07)

  • ir.sequence ของ Scan Station (เลขที่รอบนับ) ผูก company ผิดจนได้เลขที่ "New" แทนที่จะเป็น ST00001 สำหรับ user ทั่วไป — แก้แล้ว (ระบุ company_id=False ให้ชัดเจน)
  • Move Stock mode deploy แล้วแต่ browser ยังโหลด JS เก่าจาก Cloudflare cache (ปุ่มสลับโหมดกดไม่ติด) — แก้แล้ว (เพิ่ม ?v=2 ให้ URL ของ JS/CSS)
  • Internal SO/PO (ขายข้ามบริษัท) confirm แล้วไม่เคยออก invoice/vendor bill เลย ต้องบันทึกมือ — แก้แล้ว (ADR-014: ออก draft invoice/bill อัตโนมัติทันทีตอน confirm) พร้อมแก้ต้นตอ purchase_method ของ product หินที่ผูกกับ stone.material ทุกตัว (ตั้งใหม่เป็น 'purchase' เพราะระบบนี้ไม่เคย validate ใบรับสินค้าจริงเลย บิลแบบ 'receive' เดิมจะได้ยอด 0 เสมอ)
  • ไม่มีหน้าสรุปยอดรวม intercompany ระหว่าง EG↔ES — แก้แล้ว (ADR-014 Phase 2: เมนู Intercompany Reconciliation, การ์ด+drawer คลิกเปิด invoice/bill ได้ตรง)

แก้ไปแล้ว (2026-07-19)

  • Cut to Order/Select Slabs หายไปเมื่อวัสดุมี Finish variant จริง — is_stone_material/is_stone_block/is_stone_lot_material เทียบ product_id (variant เป๊ะๆ) กับ block.product_id ที่ Odoo archive ทิ้งอัตโนมัติทันทีที่ template มีหลาย variant — แก้แล้ว (เทียบที่ product_tmpl_id), รวมถึง Select Slabs wizard domain + สต็อกจริงของแผ่น (เปลี่ยนไปใช้ block.variant_id/slab.lot_id.product_id แทน) ดูรายละเอียดเต็มที่ บทที่ 13: Product Concepts หัวข้อประเภท 3
  • Cut Order wizard ผลิตผิด Finish จากที่ลูกค้าสั่งจริง (ยึด block.finish ค่าตายตัวแทน SO line) — แก้แล้ว (commit 86aa151, a879955)
  • Block ↔ Purchase Order Line ไม่ auto-fill, ไม่มี domain กรอง — ต้องกรอก Supplier/Total CBM ซ้ำเองทั้งที่มีบน PO แล้ว, ช่องเลือก PO Line โชว์ทุก PO ในระบบไม่กรองตามวัสดุ — แก้แล้ว (commit 3ad8837) ดู บทที่ 02: รับสินค้าเข้าคลัง

แก้ไปแล้ว (2026-07-22)

  • Select Slabs ข้ามบริษัท (EG↔ES) ขึ้น Access Error "doesn't have 'read' access to: Warehouse" — พบระหว่าง validate ฟีเจอร์ บทที่ 08: ขายข้ามบริษัท แบบ end-to-end จริงเป็นครั้งแรก (ก่อนหน้านี้ยังไม่เคยทดสอบผ่าน session พนักงานจริงที่ไม่ได้ติ๊ก company ปลายทางไว้ใน company selector) — stone.slab.write() เรียก _stock_move_status_change()→_get_bucket_location() อ่าน block.warehouse_id ของบริษัทอื่นโดยไม่ sudo() ซึ่งเป็น code path กลางที่ทุกโหมดการขาย 1-4 ใช้ร่วมกัน แก้แล้วด้วย .sudo() จุดเดียว (commit 58fa4df) ยืนยันผ่านทั้ง odoo shell (จำลอง session พนักงานเป๊ะๆ) และหน้าเว็บจริงซ้ำ — ยังไม่ได้ไล่ทดสอบซ้ำว่า Mode 1/3/4 ข้ามบริษัทเจอบั๊กเดียวกันมาก่อนหรือไม่ เพราะ session นี้ validate เจาะจงแค่เส้นทาง Select Slabs เท่านั้น

แก้ไปแล้ว (2026-07-20)

  • ใบรับสินค้า (Receipt) ของ PO ถ้าถูก validate จริง จะทำให้สต็อกหินซ้ำ 2 เท่า — สต็อกหิน/แผ่นทั้งหมดจัดการผ่านโค้ด custom ของโมดูลนี้เอง แยกขาดจาก native Purchase → Receipt flow ของ Odoo มาตั้งแต่ Phase 1 เดิมกันด้วยการบอกพนักงานเฉยๆ ไม่ให้กด Validate ใบรับสินค้า ไม่มีการป้องกันจริงในระบบ — แก้แล้ว 2 ชั้น: (1) auto-cancel ใบรับสินค้าที่ตรงกันทันทีที่ Block ผูกกับ PO Line, (2) hard-block (UserError) ถ้ามีใครพยายาม validate ใบรับสินค้าของสินค้าหินอยู่ดี (commit 0257ec9) ทดสอบจริงบน production ผ่านหน้าเว็บจริงแล้ว — ภาพจริงดู บทที่ 02: รับสินค้าเข้าคลัง
    บั๊กเสริมdeploy ไม่ครบระหว่างทดสอบ
    รอบแรกที่ "verify ผ่านแล้ว" คือ verify ผ่าน odoo shell เท่านั้น (process แยกต่างหาก โหลดโค้ดสดเสมอ) แต่ web worker จริงที่พนักงานใช้งานยังไม่ได้ restart จึงยังรันโค้ดเก่าอยู่ — ทดสอบผ่านหน้าเว็บจริงครั้งแรกเจอว่า validate ผ่านฉลุยไม่มี error เลย (สร้างสต็อกจริงซ้ำ 3 m³ ก่อนจับได้ — reverse คืนเรียบร้อยแล้ว) แก้โดย docker restart แล้ว re-test ผ่านหน้าเว็บซ้ำจนยืนยันบล็อกได้จริง
  • การคืนสินค้า (Returns/RMA) ไม่มีเลย — สถานะแผ่นค้าง "Sold" ตลอดไปแม้ของจริงกลับเข้าคลังแล้ว — stone.slab.status ไม่มี path ย้อนกลับจาก 'sold' เลย และ button_validate() เช็คแค่ picking ขาออก (outgoing) เท่านั้น ถ้าพนักงานใช้ปุ่ม Return มาตรฐานของ Odoo (สร้างใบรับคืนเป็น incoming) โมดูลนี้มองไม่เห็นเลย สต็อกจริงของ Odoo ถูกต้อง แต่ Select Slabs wizard/ตัวนับ Block/Stock Take ยังเห็นแผ่นนั้นเป็น Sold ตลอดไป — แก้แล้ว: เพิ่มสถานะใหม่ "Returned - Pending Inspection" ตรวจจับ native Return ผ่าน stock.move.origin_returned_move_id อัตโนมัติ แล้วให้พนักงานตัดสินใจเอง 2 ทาง (ขายต่อได้ → Available / ชำรุด → Cut Loss) ผ่านปุ่มบนฟอร์ม/list เมนูใหม่ "Slabs Pending Inspection" ดู บทที่ 23: การคืนสินค้า
