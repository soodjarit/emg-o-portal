[01] BOQ และใบเสนอราคา

ข้อประเด็นที่แจ้งผลการวิเคราะห์สถานะ
1.1ตั้งค่า Rate Library สำหรับงานที่มีหลายรูปแบบ (10+ แบบ) ซับซ้อนและไม่ยืดหยุ่นผู้ใช้ไม่ต้องตั้งหรือดูแล Rate Library อีก ราคาและสินค้าเก็บไว้ที่แต่ละบรรทัดของ BOQ ตามไฟล์ Excel ที่ Import เข้ามา แต่ละโครงการตั้งราคาต่างกันได้ ไม่ต้องสร้างรายการไว้ล่วงหน้า
  • ราคามาจากไฟล์ Excel (แยกวัสดุ / ค่าแรง) เก็บที่บรรทัด
  • บรรทัดหินจับคู่กับสินค้า FG ในระบบ (ผิวเป็นตัวเลือกของสินค้า ส่วนกว้าง ยาว หนา แยกเป็นคอลัมน์ของตัวเอง)
  • เมื่อพิมพ์รายการบริการ ระบบเสนอชื่อและราคาจากบรรทัดที่เคยทำไว้
  • ต้นทุน: จะตรวจรายละเอียดอีกครั้งตอนออกแบบ
  • ไม่มีเมนู Rate Library อีกต่อไป ชุดวัสดุสิ้นเปลือง/ค่าแรงใช้สินค้าในระบบ และสินค้าราคาตายตัว (โคม เจดีย์บัว) ใช้ราคาจากสินค้าโดยตรง

ปรับ 27 ต.ค. 2026 จากฉบับที่ส่งไปแล้ว: เดิมเขียนว่าระบบสร้าง Rate ให้เอง ตอนนี้ไม่ต้องมี Rate ในขั้นตอน Import เลย		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
1.2ต้องการนำข้อมูลจาก Excel เข้าใบเสนอราคา / BOQ โดยตรง โดยระบุกว้าง × ยาว × หนาImport จาก Excel เข้า BOQ ไม่ต้องกรอกเอง แล้วสร้างใบเสนอราคาจาก BOQ (ดูข้อ 1.6) เราออกแบบไฟล์ให้ใกล้เคียงใบเสนอราคาที่ลูกค้าใช้ ดาวน์โหลดเทมเพลตได้ในหน้าต่าง Import คอลัมน์: โซน/JOB, รายการ, สินค้าหิน, กว้าง (ซม.), ยาว (ซม.), หนา (ซม.), จำนวน, หน่วย, ราคาวัสดุ/หน่วย, ค่าแรง/หน่วย และ Overhead
ช่องสินค้าหินเลือกได้เฉพาะสินค้า FG 2 แบบ: FG แผ่นตัดตามขนาด (ต้องใส่ กว้าง ยาว หนา ครบ) และ FG ราคาตายตัว เช่น เจดีย์บัว ซุ้มบัว โคม ไม่รับ Slab หรือ Block เพราะงานติดตั้งต้องระบุขนาดอยู่แล้ว
ระบบตรวจทีละขั้น ไม่ครบไม่ไปต่อ:
  1. ตรวจโครงสร้างไฟล์ (คอลัมน์ หน่วย ตัวเลข)
  2. ตรวจรายการ: บรรทัดหินต้องจับคู่สินค้า FG ได้ และ FG แผ่นตัดที่ขาดกว้าง ยาว หรือหนา ระบบบอกว่าแถวไหนขาดอะไร บรรทัดบริการ (ค่าแรง ฯลฯ) ใช้ได้เลย ไม่ต้องสร้างรายการไว้ก่อน
  3. ดูตัวอย่างยอดวัสดุ ค่าแรง Overhead
  4. ยืนยัน ระบบสร้าง BOQ ใหม่ให้ตรวจ แล้วกด "สร้างใบเสนอราคา" (วัสดุและค่าแรง)
ทุกครั้งที่ Import ระบบสร้าง BOQ ใหม่เสมอ ไม่ทับของเดิม
คำถามถึงลูกค้า: ถ้าจำนวน ตร.ม. หารด้วยพื้นที่ 1 ชิ้นไม่ลงตัว ต้องการให้ปัดเศษอย่างไร (ตอนนี้ระบบไม่สร้างรายการชิ้น และไม่เปลี่ยน ตร.ม. หรือราคา)		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
1.3ความหนาของงานคือข้อมูลที่โรงงานต้องใช้ ไม่ใช่แค่หมายเหตุความหนาเป็นช่องของตัวเอง ไม่ใช่หมายเหตุ กรอก กว้าง × ยาว × หนา ที่บรรทัด BOQ (หรือในไฟล์ Excel) แล้วค่านั้นไปอยู่ในบรรทัดใบเสนอราคาให้เอง ไม่ต้องพิมพ์ซ้ำ ราคาไม่เปลี่ยน ใบสั่งผลิตอ่านขนาดจากบรรทัดใบเสนอราคานี้ (ดูข้อ 3.2)วิเคราะห์แล้ว · รอลูกค้ายืนยัน
1.4หา Project Code ในใบเสนอราคาไม่เจอ (อยู่ในแท็บ Other Info)ย้ายขึ้นหน้าแรกของใบเสนอราคาแล้ว ช่อง Sold as Project, Project และ Customer Reference อยู่ใต้เงื่อนไขชำระเงิน ไม่ต้องเข้าแท็บ Other Info
คำถามถึงลูกค้า: "Project Code" ที่หมายถึงคือช่องไหน (Project, Customer Reference หรือรหัสอื่น)		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
1.5Overhead มีหลายอัตรา (5%, 10%, 15%, 20%) ไม่ใช่อัตราเดียวตั้งอัตราได้ทั้งที่หัว BOQ และทีละบรรทัด ค่าตั้งต้นที่หัว BOQ คือ 10% ทุกบรรทัดใช้ค่านั้น แก้เป็น 5 / 15 / 20 ได้ทีละบรรทัด เมื่อเปลี่ยนค่าที่หัว เฉพาะบรรทัดที่ยังใช้ค่าตั้งต้นจะเปลี่ยนตาม บรรทัดที่แก้เองไม่เปลี่ยน
คำถามถึงลูกค้า: แต่ละอัตราตัดสินจากอะไร (ประเภทงาน ลูกค้า หรือขนาดงาน) จะได้ตั้งค่าเริ่มต้นให้ตรง		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
1.6ถามว่า Import เข้าใบเสนอราคา (QT) ตรงๆ ได้ไหม ทำไมต้องมี BOQควรมี BOQ และผู้ใช้ควรเห็นงานก่อนออกใบเสนอราคา ไม่ซ่อนไว้เบื้องหลัง ขั้นตอนที่เสนอ:
  1. Import ไฟล์ Excel ผ่านการตรวจทีละขั้น (ข้อ 1.2) ระบบสร้าง BOQ ให้ตรวจ
  2. ตรวจ BOQ บนหน้าจอ แก้ไขได้ถ้าจำเป็น
  3. กด "สร้างใบเสนอราคา" ขั้นตอนเดียว (มีปุ่มนี้อยู่แล้ว)
จึงเพิ่มแค่การ Import เข้า BOQ ส่วนจาก BOQ ไปใบเสนอราคาใช้ของเดิม
BOQ ให้ 2 อย่างที่ใบเสนอราคาเดี่ยวๆ ไม่มี:
  1. ที่พักตรวจงานก่อนออกใบเสนอราคา
  2. แก้งานได้โดยไม่แตะใบเสนอราคาที่ส่งลูกค้าไปแล้ว
หน้าที่อื่นของ BOQ (หัวข้อ [04]) ย้ายไปอยู่บนใบเสนอราคาได้ในทางเทคนิค แต่ใบเสนอราคาใช้ร่วมกับการขายปกติทุกใบ จึงเสนอให้คง BOQ ไว้ก่อน
คำถามถึงลูกค้า: หลังส่งใบเสนอราคาแล้ว แก้ราคาบ่อยแค่ไหน (ถ้าบ่อยมาก การมีสองเอกสารจะเป็นภาระ ต้องกลับมาทบทวน)
ปรับ 27 ต.ค. 2026 จากฉบับที่ส่งไปแล้ว: ลดเหตุผลเหลือ 2 ข้อที่ BOQ ให้ได้จริง และปรับหัวข้อ [04]		วิเคราะห์แล้ว · รอลูกค้ายืนยัน

[02] การผลิต (MO) และคลังสินค้า

ข้อประเด็นที่แจ้งผลการวิเคราะห์สถานะ
2.1สร้างไอเทม Block ใหม่ใน PO แล้วระบบไม่คำนวณปริมาณ / ต้นทุน CBM ให้อัตโนมัติสาเหตุ: ไอเทม Block ที่สร้างโดยตรงในช่องสินค้าของ PO ไม่ผ่าน Material (ค่า density เก็บไว้ที่ Material) ระบบจึงแปลง ตัน ↔ CBM และคิดต้นทุนต่อ CBM ให้ไม่ได้ พบในไอเทม MOLEANOS BEIGE-BLOCK
  • แก้แล้ว: เลือกไอเทม Block ที่ยังไม่ผูก Material ระบบเตือนทันที และมีแถบเตือนบนหัว PO พร้อมปุ่มไป "Quick Material Setup" (Stone > Tools) ซึ่งสร้าง Block / Slab ให้พร้อมกันและเก็บ Density
  • ข้อมูลเดิม: สร้าง Material "โมลีโนส เบจ / MOLEANOS BEIGE" (density 2.8) พร้อม Block และ Slab ให้แล้ว ทดสอบกรอก 10 ตัน ได้ 3.5714 CBM ตามสูตร ส่วนไอเทมเดิม 2 ตัวและ Block ที่รับไปแล้วใน PO P00505–P00507 ไม่ได้แก้
คำถามถึงลูกค้า: ยืนยัน density 2.8 และราคาขาย Block ของ MOLEANOS BEIGE (ตอนนี้ตั้งเป็น 71,550 บาท/CBM ตามไอเทมเดิม) ถูกต้องหรือไม่		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
2.2ใน MO ของงานตัด FG รายการวัตถุดิบแสดงเลข Slab ปนมาด้วยสาเหตุ: ช่องเลือก Lot ในแท็บ "Slab ที่จะตัด" ของ MO ตัด FG ไม่มีตัวกรอง จึงแสดงทุก lot ในระบบ (Block, Slab ของหินชนิดอื่น, FG) ปนกัน
  • แก้แล้ว: เสนอเฉพาะ Slab ของวัสดุเดียวกับ FG ที่ผลิต (ทุกผิว/ความหนา) และต้องมีสต็อกเหลือ ทดสอบกับ MO ของ SHANDONG BLACK: เห็นเฉพาะ Slab ของ SHANDONG ส่วน Slab/Block ของ NERO ไม่ขึ้นแล้ว
  • ถ้าใส่ lot ของวัสดุอื่นด้วยวิธีใดก็ตาม ระบบจะไม่ยอมบันทึก พร้อมแจ้งข้อความชัดเจน
  • ปุ่ม "เลือก Slab อัตโนมัติ" ทำงานเหมือนเดิม
คำถามถึงลูกค้า: ในที่ประชุมบันทึกว่าต้องการเห็น "เฉพาะ Block" แต่ MO ตัด FG ใช้ Slab เป็นวัตถุดิบ (Block ใช้ในใบตัด Slab) ขอยืนยันว่ารายการที่ควรเห็นในใบตัด FG คือ Slab ของวัสดุนั้นใช่ไหม		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
2.3กรอกขนาด Slab ทีละแผ่น (30–80 แผ่นต่อล็อต) เป็นงานหนักใช้ Excel แทนปุ่มคัดลอก ตามที่ตกลงในที่ประชุม กรอกขนาดครั้งเดียวต่อกลุ่ม แล้วใส่ "จำนวนชิ้น" — แผ่นขนาดเดียวกันกี่แผ่นก็ได้ในแถวเดียว ระบบแตกเป็นแผ่นละ 1 แถวให้เอง (แผ่นที่มี Serial แยกกัน) ไม่ต้องคัดลอกทีละแถว
ใช้ได้แล้วที่ใบรับของ: ปุ่ม "Import Slab จาก Excel" (ผู้ใช้แจ้งซ้ำ 21 ต.ค. Helpdesk HT00148)		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
2.4แก้ขนาดใน Excel แล้วต้องใส่กลับเข้าระบบExport แก้ในไฟล์ แล้ว Import กลับได้แล้ว ที่ใบรับของ Slab มีปุ่ม "Export Slab เป็น Excel" ได้ไฟล์รูปแบบเดียวกับ template พร้อมแถวที่กรอกไว้ แก้ขนาดหรือเพิ่ม/ลบแถวในไฟล์ แล้วอัปโหลดกลับที่ "Import Slab จาก Excel"
  • ระบบแทนที่แถว Slab เดิมของสินค้าในไฟล์ทั้งหมด ไม่ซ้ำแถว และแจ้งจำนวนแถวที่จะถูกแทนก่อนยืนยัน
  • ตรวจทีละแถวเหมือนเดิม ถ้ามีแถวผิดจะยืนยันไม่ได้
  • ใช้ได้เฉพาะใบรับของที่ยังไม่ Validate (หลัง Validate ยัง Export ไปดูได้อย่างเดียว)
วิเคราะห์แล้ว · รอลูกค้ายืนยัน
2.5ต้องการคอลัมน์ลำดับเลข Slab เพื่อตรวจสอบและติดตามเพิ่มคอลัมน์ "ลำดับ" 1..n แล้ว ที่ Details ของใบรับของ ในไฟล์ Excel (Export/Import) และคู่กับ Serial code เพื่อใช้นับแผ่นเทียบของจริง
  • Serial code ที่ระบบรันให้ (SLB-yy-nnnn) เกิดตอน Validate — ก่อน Validate ช่องนี้ว่างได้หรือกรอกเองได้
  • หลัง Validate กด Export จะเห็นลำดับพร้อม Serial code ของทุกแผ่น
คำถามถึงลูกค้า: "ลำดับเลข Slab" หมายถึงเลขลำดับแถว 1..n อย่างเดียวใช่ไหม หรือต้องการเก็บเลขแผ่นของ supplier ด้วย (ถ้าใช่ ต้องเพิ่มช่องเก็บที่ตัว Slab)		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
2.6ทำ MO ที่ตัดสต็อกแล้ว สินค้าที่ผลิตไม่เข้าคลังทดสอบแล้ว ไม่พบความผิดปกติ เราทดสอบวงจรใบสั่งผลิต FG ครบ 1 รอบ (นำเข้า BOQ → ใบเสนอราคา → ผลิต FG 2 ใบ → ส่งของ) พร้อมนับสต็อกก่อนและหลังทุกขั้น: Slab ถูกตัดออกตามที่ใช้จริง FG เข้าคลังครบ ขนาดและจำนวนชิ้นตรงตามที่สั่ง และสต็อกลดตรงหลังส่งของ ดูเอกสารผลทดสอบ
ถ้ายังพบอีก: ขอเลขที่ MO ชนิดของ MO และปุ่มที่กดปิดงาน เพื่อทดสอบซ้ำให้ตรงเคส		วิเคราะห์แล้ว · รอลูกค้ายืนยัน

[03] การแสดงผลและการใช้งาน

ข้อประเด็นที่แจ้งผลการวิเคราะห์สถานะ
3.1ค่ากว้าง × ยาว ของ FG ไม่แสดงในคอลัมน์หลักของรายการสินค้าแสดงที่บรรทัดใบเสนอราคาแล้ว คอลัมน์ "ขนาด / ราคา" ของบรรทัด FG แสดงขนาดและจำนวนชิ้นตามรายชิ้นที่ใส่ไว้ เช่น "50 × 90 ซม. × 20 ชิ้น · หนา 2 ซม." ถ้าบรรทัดเดียวมีหลายขนาด แสดงทุกขนาดเรียงกัน อ่านได้ทันทีโดยไม่ต้องเปิดรายชิ้นวิเคราะห์แล้ว · รอลูกค้ายืนยัน
3.2ความหนาของ FG ต้องส่งต่อถึงใบสั่งผลิตให้ถูกต้องขนาดและความหนาไปถึงใบสั่งผลิตแล้ว ค่ากว้าง × ยาว × หนา จาก BOQ ไปอยู่ในบรรทัดใบเสนอราคา และเข้ารายการชิ้นตัดของใบสั่งผลิต พร้อมความหนาของแต่ละชิ้น ถ้า ตร.ม. หารด้วยพื้นที่ 1 ชิ้นลงตัว ระบบสร้างรายการชิ้นให้ (เช่น 9 ตร.ม. ÷ 0.45 = 20 ชิ้น) ถ้าไม่ลงตัว ไม่สร้างรายการชิ้นและไม่เปลี่ยน ตร.ม. หรือราคา
เพิ่มความปลอดภัยเรื่องสต็อก: เดิมระบบเช็คแค่ว่ามี FG ตัวนี้พอไหม โดยไม่ดูขนาด ทำให้อาจขายของที่ไม่มีจริงได้ ตอนนี้:
  • ตอนขาย ระบบนับเฉพาะสต็อก FG ที่ขนาดและความหนาตรงกับที่สั่ง และแสดงในคอลัมน์ "สต็อก FG ตรงขนาด"
  • ใบส่งของจองเฉพาะแผ่นที่ขนาดตรง ถ้าไม่มีก็รอ ไม่หยิบแผ่นผิดขนาดให้
  • ส่งของบางส่วนและคืนของ ยังจองเฉพาะแผ่นขนาดตรง (ส่งได้ทีละทั้งแผ่น ตามกฎเดิมของระบบ)

[04] BOQ ทำอะไรให้ในระบบ (หน้าที่ของ BOQ)

ประกอบข้อ 1.6 — เหตุผลที่ Import เข้า BOQ ก่อน แล้วค่อยสร้างใบเสนอราคา

ข้อหน้าที่ของ BOQทำอะไรให้ถ้าย้ายมาไว้ที่ใบเสนอราคา
4.1แยกใบวัสดุ / ใบค่าแรงสร้างใบเสนอราคาเป็นสองใบจากข้อมูลชุดเดียว ใบวัสดุและใบค่าแรง เพื่อให้ออก PO แยกสองฝั่งต้องเก็บราคาวัสดุและค่าแรงแยกที่ทุกบรรทัดของใบเสนอราคา และสร้างสองใบจากใบเดียว
4.2สรุปท้ายใบPreliminaries, Overhead & Profit, Performance Security และหัก ณ ที่จ่าย คำนวณจากยอดและอัตราที่ตั้งไว้ใน BOQต้องย้ายที่เก็บอัตราและฐานคำนวณมาไว้ที่ใบเสนอราคา
4.3Cut List ที่มาทีหลังนำเข้าและเทียบ Cut List หลังขาย รวมงานโคม / เจดีย์บัวที่ราคาตั้งไว้ก่อนแล้วมีรายการตัดตามมาต้องย้ายลิงก์ไป Cut List และบรรทัดสูตรของโคม / เจดีย์บัวมาไว้ที่ใบเสนอราคา
4.4เทียบยอดที่เสนอกับยอดจริงเก็บยอดตอนเสนอราคาไว้ เมื่อเลือก Slab จริงแล้วยอดเปลี่ยน ระบบเทียบและเตือนเมื่อสรุปท้ายใบไม่ตรงยอดตั้งต้นเก็บที่ใบเสนอราคาอยู่แล้ว ย้ายได้ไม่ยาก
4.5ตารางงานโครงการระยะเวลาและ milestone ต่อโซน คัดลอกไปยังใบเสนอราคาตอนสร้าง เพื่อใช้วางแผนงานและเรียกเก็บเงินตามงวดต้องย้ายระยะเวลาและ milestone ต่อโซนมาไว้ที่บรรทัดของใบเสนอราคา
