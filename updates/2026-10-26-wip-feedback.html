[01] BOQ และใบเสนอราคา

ข้อประเด็นที่แจ้งผลการวิเคราะห์สถานะ
1.1ตั้งค่า Rate Library สำหรับงานที่มีหลายรูปแบบ (10+ แบบ) ซับซ้อนและไม่ยืดหยุ่นผู้ใช้ไม่ต้องตั้งหรือดูแล Rate Library อีก ราคาและสินค้าเก็บไว้ที่แต่ละบรรทัดของ BOQ ตามไฟล์ Excel ที่ Import เข้ามา แต่ละโครงการตั้งราคาต่างกันได้ ไม่ต้องสร้างรายการไว้ล่วงหน้า
  • ราคามาจากไฟล์ Excel (แยกวัสดุ / ค่าแรง) เก็บที่บรรทัด
  • บรรทัดหินจับคู่กับสินค้าในระบบ (ชื่อหิน + ผิว + หนา)
  • เมื่อพิมพ์รายการบริการ ระบบเสนอชื่อและราคาจากบรรทัดที่เคยทำไว้
  • ต้นทุน: จะตรวจรายละเอียดอีกครั้งตอนออกแบบ
  • ไม่มีเมนู Rate Library อีกต่อไป ชุดวัสดุสิ้นเปลือง/ค่าแรงใช้สินค้าในระบบ และสินค้าราคาตายตัว (โคม เจดีย์บัว) ใช้ราคาจากสินค้าโดยตรง

ปรับ 27 ต.ค. 2026 จากฉบับที่ส่งไปแล้ว: เดิมเขียนว่าระบบสร้าง Rate ให้เอง ตอนนี้ไม่ต้องมี Rate ในขั้นตอน Import เลย		วิเคราะห์แล้ว · รอลูกค้ายืนยัน
1.2ต้องการนำข้อมูลจาก Excel เข้าใบเสนอราคา / BOQ โดยตรง โดยระบุกว้าง × ยาว × หนาImport จาก Excel เข้า BOQ ไม่ต้องกรอกเอง แล้วสร้างใบเสนอราคาจาก BOQ (ดูข้อ 1.6) ไฟล์ใช้รูปแบบใกล้เคียงใบเสนอราคาที่ลูกค้าใช้ มีโซน/JOB, รายการ, ชื่อหิน, ผิว, หนา, กว้าง, ยาว, จำนวน, หน่วย, ราคาวัสดุ/หน่วย, ราคาค่าแรง/หน่วย และ Overhead ที่หัวไฟล์
ระบบตรวจทีละขั้น ไม่ครบไม่ไปต่อ:
  1. ตรวจโครงสร้างไฟล์ (คอลัมน์ หน่วย ตัวเลข)
  2. ตรวจรายการ: บรรทัดหินต้องจับคู่สินค้าได้ก่อนไปต่อ บรรทัดบริการ (ค่าแรง ฯลฯ) ใช้ได้เลย ไม่ต้องสร้างรายการไว้ก่อน
  3. ดูตัวอย่างยอดวัสดุ ค่าแรง Overhead
  4. ยืนยัน ระบบสร้าง BOQ ให้ตรวจ แล้วกด "สร้างใบเสนอราคา" (วัสดุและค่าแรง)
วิเคราะห์แล้ว · รอลูกค้ายืนยัน
1.3ความหนาของงานคือข้อมูลที่โรงงานต้องใช้ ไม่ใช่แค่หมายเหตุ—รอวิเคราะห์
1.4หา Project Code ในใบเสนอราคาไม่เจอ (อยู่ในแท็บ Other Info)—รอวิเคราะห์
1.5Overhead มีหลายอัตรา (5%, 10%, 15%, 20%) ไม่ใช่อัตราเดียว—รอวิเคราะห์
1.6ถามว่า Import เข้าใบเสนอราคา (QT) ตรงๆ ได้ไหม ทำไมต้องมี BOQควรมี BOQ และผู้ใช้ควรเห็นงานก่อนออกใบเสนอราคา ไม่ซ่อนไว้เบื้องหลัง ขั้นตอนที่เสนอ:
  1. Import ไฟล์ Excel ผ่านการตรวจทีละขั้น (ข้อ 1.2) ระบบสร้าง BOQ ให้ตรวจ
  2. ตรวจ BOQ บนหน้าจอ แก้ไขได้ถ้าจำเป็น
  3. กด "สร้างใบเสนอราคา" ขั้นตอนเดียว (มีปุ่มนี้อยู่แล้ว)
จึงเพิ่มแค่การ Import เข้า BOQ ส่วนจาก BOQ ไปใบเสนอราคาใช้ของเดิม
BOQ ให้ 2 อย่างที่ใบเสนอราคาเดี่ยวๆ ไม่มี:
  1. ที่พักตรวจงานก่อนออกใบเสนอราคา
  2. แก้งานได้โดยไม่แตะใบเสนอราคาที่ส่งลูกค้าไปแล้ว
หน้าที่อื่นของ BOQ (หัวข้อ [04]) ย้ายไปอยู่บนใบเสนอราคาได้ในทางเทคนิค แต่ใบเสนอราคาใช้ร่วมกับการขายปกติทุกใบ จึงเสนอให้คง BOQ ไว้ก่อน
คำถามถึงลูกค้า: หลังส่งใบเสนอราคาแล้ว แก้ราคาบ่อยแค่ไหน (ถ้าบ่อยมาก การมีสองเอกสารจะเป็นภาระ ต้องกลับมาทบทวน)
ปรับ 27 ต.ค. 2026 จากฉบับที่ส่งไปแล้ว: ลดเหตุผลเหลือ 2 ข้อที่ BOQ ให้ได้จริง และปรับหัวข้อ [04]		วิเคราะห์แล้ว · รอลูกค้ายืนยัน

2.2ใน MO ของงานตัด FG รายการวัตถุดิบแสดงเลข Slab ปนมาด้วย—รอวิเคราะห์

2.5ต้องการคอลัมน์ลำดับเลข Slab เพื่อตรวจสอบและติดตาม—รอวิเคราะห์
2.6ทำ MO ที่ตัดสต็อกแล้ว สินค้าที่ผลิตไม่เข้าคลัง—รอวิเคราะห์

[04] BOQ ทำอะไรให้ในระบบ (หน้าที่ของ BOQ)

ประกอบข้อ 1.6 — เหตุผลที่ Import เข้า BOQ ก่อน แล้วค่อยสร้างใบเสนอราคา

ข้อหน้าที่ของ BOQทำอะไรให้ถ้าย้ายมาไว้ที่ใบเสนอราคา
4.1แยกใบวัสดุ / ใบค่าแรงสร้างใบเสนอราคาเป็นสองใบจากข้อมูลชุดเดียว ใบวัสดุและใบค่าแรง เพื่อให้ออก PO แยกสองฝั่งต้องเก็บราคาวัสดุและค่าแรงแยกที่ทุกบรรทัดของใบเสนอราคา และสร้างสองใบจากใบเดียว
4.2สรุปท้ายใบPreliminaries, Overhead & Profit, Performance Security และหัก ณ ที่จ่าย คำนวณจากยอดและอัตราที่ตั้งไว้ใน BOQต้องย้ายที่เก็บอัตราและฐานคำนวณมาไว้ที่ใบเสนอราคา
4.3Cut List ที่มาทีหลังนำเข้าและเทียบ Cut List หลังขาย รวมงานโคม / เจดีย์บัวที่ราคาตั้งไว้ก่อนแล้วมีรายการตัดตามมาต้องย้ายลิงก์ไป Cut List และบรรทัดสูตรของโคม / เจดีย์บัวมาไว้ที่ใบเสนอราคา
4.4เทียบยอดที่เสนอกับยอดจริงเก็บยอดตอนเสนอราคาไว้ เมื่อเลือก Slab จริงแล้วยอดเปลี่ยน ระบบเทียบและเตือนเมื่อสรุปท้ายใบไม่ตรงยอดตั้งต้นเก็บที่ใบเสนอราคาอยู่แล้ว ย้ายได้ไม่ยาก
4.5ตารางงานโครงการระยะเวลาและ milestone ต่อโซน คัดลอกไปยังใบเสนอราคาตอนสร้าง เพื่อใช้วางแผนงานและเรียกเก็บเงินตามงวดต้องย้ายระยะเวลาและ milestone ต่อโซนมาไว้ที่บรรทัดของใบเสนอราคา
